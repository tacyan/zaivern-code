# Windows の zai update 修正・検証記録

対象: d78defa (0.24.2) を基点とする fix/windows-update。
検証日: 2026-09-11。ホスト: Windows、rustc 1.97.1。

## 修正

- Windows の CLI を console subsystem とし、標準入出力とシェルの終了待ちを維持する。
  GUI 判定後はコンソールなしの子プロセスへ引き継ぐ。team run の副作用は繰り返さない。
- Windows PowerShell の API 応答を UTF-8 に固定する。従来の出力では、公開リリース情報が
  invalid escape となる現象を実バイナリから再現した。
- Windows は .cargo/bin の配置でも同梱インストーラを使用する。
  インストーラはこのディレクトリにも配布版を置くため、場所だけでソースビルドと判断しない。
- 同梱スクリプトを UTF-8 の標準入力で PowerShell 5.1 へ渡す。
  PSModulePath を子に継承せず、5.1 自身が標準モジュールを解決できるようにする。
- 現在の exe の配置先だけを更新する。PATH、他の配置先、アプリ登録は変更しない。
- インストーラ失敗は例外にし、CLI に非ゼロの終了コードを返す。
- 配布物は呼び出しごとの一時ディレクトリへ取得し、SHA-256 検証後に展開する。
- ファイルは別名へコピーしてから排他ロック下で差し替える。配置失敗時は復元を試みる。
  共有違反 (Win32 32/33) だけを最大10秒、進捗表示付きで再試行する。
- Windows PowerShell 5.1 が日本語入りスクリプトを読めるよう、UTF-8 BOM を付ける。

## 確認済み

- Windows ネイティブの実バイナリをソースからビルド。
- PE ヘッダの subsystem が console (3) であること。
- --version、update --help の表示と終了コード 0。
- update --invalid のエラー表示と終了コード 2。
- 専用の一時 ZAIVERN_HOME による update --check。
  v0.24.2 を取得し、「最新です。更新の必要はありません。」と表示して正常終了。
- 更新手段3件、起動マーカー1件、UTF-8・標準モジュール・成功/失敗通知のテスト。
- tools/windows-installer-test.ps1 の既定実行:
  チェックサム17件、模擬インストーラ12件、使用中exeの置換、コピー失敗、復元、
  共有違反からの回復、恒久的共有違反の時限、権限エラーを再試行しないこと。
- 実更新統合テスト:
  cargo test --bin zai windows_update_downloads_and_replaces_running_exe -- --ignored --nocapture
  現在版を0.0.0とする入力を同じ更新ディスパッチへ与え、確認入力 y、公開リリースの取得、
  SHA-256検証、実行中テストexeの置換、完了表示、新exeの --version まで成功。
  実行時間65.01秒。取得した版はv0.24.2。
  同一ソースからコンパイルしたテストexeのコピーを使用し、exe・設定・TEMP/TMPは
  専用領域、子プロセスは独立グループと180秒上限。実ユーザーのPATH・配置先は変更しない。
- 別エージェントによる更新先・排他・失敗通知・テスト隔離の反証レビュー。
  実際に排他ロックを保持すると約10秒で失敗して元ファイルを保持し、解放後は更新成功。

## 再現した問題と解消

- 初回起動直後のexeで共有違反が発生した。別エージェントの異なるfixture2個では、
  プロセス生存中の再試行が2847ms / 1809ms後に成功。保持主体は未特定で、
  ウイルス対策等が原因とは断定しない。上限付き再試行後、既定の置換試験は成功した。
- PowerShell 7 のモジュールパス継承時に5.1の Get-FileHash / Expand-Archive が
  見つからないことを比較試験で確認。子で継承しない場合は両方を取得し、正常終了した。

## 検証の限界

- 公開版の取得が必要な統合テストは既定ではignore。今回の明示実行は成功した。
- GUIの実表示・フォーカスは未確認。スタートメニュー等からconsole exeを直接起動すると、
  GUI子プロセスへの引き継ぎ前にコンソールが一瞬表示される可能性がある。
- 使用中で削除できないGUID付き .old は残す。後日自動削除する仕組みはない。
- tools/windows-check.sh はcargo-xwin不在。代わりにWindowsネイティブで検証した。
- tools/linux-test.sh cli:: はDocker未起動。Linux/macOSの実行は未確認。
- MSVCのライブラリ生成メッセージが linker_messages 警告として出力された。
  抑制していない。検証スクリプトの「警告ゼロ」表示とこの実出力は一致しない。
- 公開・リリースは実施しない。既存のGUI subsystem版へは修正版exeの初回反映が必要。
