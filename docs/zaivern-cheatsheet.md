# Zaivern基本操作チートシート

**まずは「フォルダを開く → AIを追加する → 小さな仕事を頼む」の3つから始めましょう。**
複数AIでの開発は、その後にTeam機能で試せます。

画面名はv0.24.1の日本語表示を基準にしています。版や設定によって表示が異なる場合があります。

## 最初に知っておく言葉

| 言葉 | 意味 |
|---|---|
| ターミナル | コマンドを入力するアプリ。macOS・Linuxではターミナル、WindowsではPowerShellなどを使います |
| コマンド | `zai .` のような、パソコンに実行させる短い指示。入力後にEnterを押します |
| エージェント | 依頼を受けてファイルを調べたり、コードを書いたりするAI |
| 作業フォルダ | 今回作成・変更するファイルを置く場所 |
| Team Run | 複数の担当へ仕事を配る、一回のチーム実行 |
| SPEC.md | 作りたいものや完了条件を書いたテキストファイル |

**コマンドはターミナルへ、作ってほしい内容はAIの入力欄へ。** この区別を覚えると迷いにくくなります。

## 1．使える状態か確認する

Zaivernに加えて、対応するAI CLIを最低一つインストールし、サインインしておきます。
ZaivernにはAIモデルやAIサービスの利用契約は含まれません。

ターミナルで次を実行します。

```sh
zai --version
```

バージョンが表示されれば、Zaivernのコマンドを呼び出せています。
未導入の場合は、[日本語READMEのインストール手順](../README.ja.md)から始めてください。

## 2．作業フォルダを開く

**操作する場所：パソコンのターミナル**

初めてなら、新しい練習用フォルダで試します。次を1行ずつ実行してください。
`zaivern-practice` が既にある場合は、別の名前に置き換えます。

```sh
mkdir zaivern-practice
cd zaivern-practice
zai .
```

- `mkdir`：フォルダを作ります。
- `cd`：そのフォルダへ移動します。
- `zai .`：現在のフォルダをZaivernで開きます。「.」は現在の場所という意味です。

既存プロジェクトなら、そのフォルダへ移動して `zai .` だけを実行します。
**画面に表示された作業フォルダが、今回の対象か確認してください。**

## 3．AIを1体追加して依頼する

**操作する場所：Zaivernの画面**

1. 「+ Agent」を押します。
2. インストール済みのAI CLIを選びます。
3. 開いたエージェントの端末へ依頼を入力し、送信します。
4. 質問や承認待ちが出たら、内容を読んで返答します。

既存プロジェクトで、最初に貼り付ける依頼の例です。

> このフォルダを調べ、何をするプロジェクトか日本語で説明してください。起動方法とテスト方法も教えてください。まだファイルは変更しないでください。

空の練習用フォルダなら、次を試せます。

> 自己紹介用の小さなWebページを作ってください。index.htmlとstyle.cssを使い、外部ライブラリは不要です。スマホでも読めるようにし、完成したらファイルの開き方を教えてください。

承認は、AIからの「この操作を実行してよいですか？」という確認です。
分からない操作は、目的と変更対象を説明してもらってから判断します。

## 4．複数AIへ分担させる

**操作する場所：ZaivernのTeam画面**

1. コマンドパレットを開きます。初期設定はmacOSが **⌘＋Shift＋P**、Windows・Linuxが **Ctrl＋Shift＋P** です。変更済みなら自分の割り当てを使います。
2. `New Team Run` と入力し、表示された項目を選びます。
3. 「SPECの渡し方」で「直接入力」を選びます。
4. 「仕様」欄へ、作ってほしい内容を入力します。
5. 「使うエージェント」を選びます。
6. 「最大エージェント数」は、最初は2にします。人数の「おまかせ」を外すと手動で指定できます。
7. 承認モードを確認し、「▶ この計画でチームを開始」を押します。

初回は承認モードを「毎回きく」にすると、要求される操作を確認しながら進められます。
開始後は担当仕様の作成を経て実装へ進む場合があります。旧版で「Plan Preview」が出た場合は、計画を確認して「Start Team」を押します。

**「+ Agent」はAI端末を追加する操作、Teamは仕事を担当へ分ける機能です。**
AIを2体追加しただけで、一つの依頼が自動分担されるわけではありません。

### Teamに貼り付ける依頼例

> 小さなサービス紹介ページを作ってください。担当1はindex.htmlの文章と構造、担当2はstyle.cssのデザインを作成してください。共通クラスはhero、features、faqとします。HTMLからCSSを読み込み、外部ライブラリは使わないでください。統合後にスマホ幅とPC幅で表示を確認し、未確認事項も報告してください。

「何を作るか」「誰がどのファイルを作るか」「何を確認すれば完成か」を書くと、分担しやすくなります。
同時実行数を増やすとAIの利用量も増える可能性があるため、各サービス側の利用状況も確認します。

## 5．仕様をファイルから渡す場合

**操作する場所：エディタで保存した後、作業フォルダのターミナル**

繰り返し使う依頼は、作業フォルダの中に `SPEC.md` という名前で保存します。
中身は、目的、担当ファイル、接続仕様、完了条件、原依頼を書いた文章です。
名前が `SPEC.md.txt` になっていないか確認してください。

計画だけを確認するには：

```sh
zai team plan SPEC.md --agents 2
```

**このコマンドではAIの実装は始まりません。** 担当と依存関係を確認します。

TeamのGUIへ渡すには：

```sh
zai team run SPEC.md --agents 2
```

画面の開始手順に従ってください。`--agents 2` は最大同時実行数で、タスクを2件に減らす指定ではありません。
詳しい書式は[並列開発仕様](team-parallel-spec.md)を参照してください。

## 6．進捗を見る・止める・再開する

**操作する場所：Team画面、または対象フォルダのターミナル**

| やりたいこと | コマンド | 起きること |
|---|---|---|
| 状態を確認する | `zai team status` | 保存されたRunの状態を表示します |
| 未完了の仕事を開き直す | `zai team resume` | 未完了のRunをGUIで開き直します |
| 新しい割り当てを止める | `zai team stop` | 新規割り当てを止めます。実行中のAIの停止は画面の確認に従います |

止まって見えるときは、まず **承認待ち・質問待ち・他担当の完了待ち・エラー** を確認します。
`stop` を実行しただけで全プロセスが終了したとは判断せず、画面の状態を確かめてください。

## 7．完成したファイルを確認する

**操作する場所：作業フォルダ、エディタ、作成したアプリやブラウザ**

- [ ] 依頼したファイルがある。
- [ ] ファイルを開く、ボタンを押すなど、実際の操作ができる。
- [ ] 依頼した内容が揃っている。
- [ ] テストや表示確認の結果がある。
- [ ] 未確認・失敗・反映保留が残っていないか分かる。

Webページの例なら、`index.html` をブラウザで開き、デザインとスマホ幅での表示を確認します。
ファイルが見つからない場合は、Teamの成果物の場所と反映エラーを確認してください。

**AIの「完了」と、自分が使える状態になったことは、両方確認します。**
成果を確認する前にRunや作業フォルダを削除しないでください。閉じる際に保持か破棄かを聞かれたら、確認が済むまでは保持します。

## 困ったときの早見表

| 困っていること | 最初に試すこと |
|---|---|
| `zai` が見つからない | インストーラのPATH案内を確認し、設定後にターミナルを開き直す。PATHは実行ファイルを探す場所の設定です |
| AIが一覧にない・起動しない | 普段のターミナルで同じAI CLIを起動し、サインインを確認する。CLIを追加した直後ならZaivernも再起動する |
| `SPEC.md` が見つからない | 保存先、ファイル名、ターミナルの現在のフォルダを確認する |
| 2体にしたのに同時に動かない | 担当ファイルの重複、依存関係、承認待ちを確認する |
| 説明と画面が違う | `zai --version` と `zai team --help` で版と対応コマンドを確認する |
| 更新の有無を知りたい | `zai update --check` を実行する |

## 慣れてから：Gitの競合調整

Gitはファイルの変更履歴を管理する道具です。Gitを使うプロジェクトで追加の競合調整を導入したい場合だけ、次を使います。
最初のAI起動で必須の操作ではありません。

| コマンド | 用途 |
|---|---|
| `zai czero init --dry-run` | 導入による変更予定を見る |
| `zai czero init` | 内容を確認したうえで、現在のリポジトリへGitフックなどを追加する |
| `zai czero doctor` | 導入状態と保護範囲を診断する |
| `zai czero verify` | 使い捨てのリポジトリで保護動作を検証する |

競合調整を入れても、異なるファイル間のAPIやデータ形式の食い違いは別途確認が必要です。
詳細は[競合調整の説明](conflict-zero.md)と[Teamの説明](team.md)を参照してください。
