# 出荷前の関門 — 「誰も動かしていない層」を無くす

`tools/release-gate.sh` と `tools/remote-check.sh` が何のためにあるのかを書く。
再発したときは、まずここを読む。

```sh
tools/release-gate.sh          # リリース前に必ずこれ 1 本
tools/release-gate.sh --quick  # 手元の速い確認 (docker / windows / 全テストを省く)
tools/release-gate.sh --list   # 段の一覧
```

---

## 1. なぜ要るのか — 0.18 系で 4 件が出荷まで生き残った

| # | どこ | 何が起きたか | なぜテストが緑だったか |
|---|------|--------------|------------------------|
| 1 | スマホ | 端末 (`#scr`) と一覧 (`#alist`) が**同時に**見えた | `#alist.mid` が `#alist { display:none }` と**詳細度が同じで後ろにある**ので勝っていた。CSS を評価しているテストが 1 本も無かった |
| 2 | スマホ | エージェントのチップを押しても切り替わらない | 遡って追従を止めたままだとポーリングが 1 本も無く、押しても永久に変わらない。**タイマーの有無**を見ているテストが無かった |
| 3 | PC | 小さなライブ枠が PTY を縮め、CLI が会話を描き直して履歴が二重になった | 実バイナリを起こして**中身**まで見ていなかった |
| 4 | i18n | `tr("…\` と行を継ぎ足した 71 箇所が走査に現れず、どの言語でも日本語のまま | 走査 (`scan_source_literals`) が行継続を知らず、`zai i18n missing` も番人も **0 件**と答えていた |

共通点はひとつだけである。

> **どれも「実際に動かせば 5 秒で分かる」のに、誰も動かしていない層にあった。**

Rust の単体テストはソースの**文字列**を見る。ブラウザの DOM も CSS も 1 度も
評価しない。**評価していないものは検査できない。**
1〜2 は評価していない層 (CSS カスケード / タイマー)、3 は起こしていない層
(実 PTY のサイズ変更)、4 は走査そのものの穴だった。

そしてもうひとつ、道具の側の問題があった。**道具は揃っていた**
(`verify.sh` / `gui-smoke.sh` / `linux-test.sh` / `windows-check.sh` /
`zai i18n missing`)。走らせるかどうかが**人の記憶に委ねられていた**だけである。
覚えていないと走らない検査は、無いのと同じ意味しか持たない。

---

## 2. 層の地図 — どの道具が何を見ているか

| 層 | 見るもの | 道具 | 無い環境では |
|----|----------|------|--------------|
| 0 | ソースの文字列・構造 | `cargo test` (番人テスト群) | 常に走る |
| 1 | 整形 / 警告 / clippy | `tools/verify.sh --lint` | 常に走る |
| 2 | **CSS の詳細度の法則** | `cli::tests::スマホのcssは隠したものを脇道から見せない` | 常に走る (ブラウザ不要) |
| 3 | **スマホ画面を本当に描く** | `tools/remote-check.sh` | node / Chromium が無ければ `[skip]` |
| 4 | 実バイナリの生存 | `tools/gui-smoke.sh` | 画面が開けなければ `[skip]` |
| 5 | Linux / Windows | `tools/linux-test.sh` / `tools/windows-check.sh` | docker / cargo-xwin が無ければ `[skip]` |
| 6 | 訳の穴 | `zai i18n missing` | 常に走る |

`tools/release-gate.sh` はこれを**上から順に 1 本で**通す。段を足したい人は
スクリプト先頭の `STEPS` に 1 語足すだけでよい (入口は増やさない)。

**`[skip]` は緑ではない。** 関門は最後に `緑 N / 赤 N / 未確認 N` を出し、
未確認があればラベルにそう書く。CI では `[skip]` を**不合格**にしている
(確かめられる前提が揃っている場所で降りたなら、それは環境の壊れである)。

## 3. スマホ画面を「本当に描く」検査

```sh
tools/remote-check.sh              # 4 通り (狭い / 空 / 英語 / 旧 PC)
tools/remote-check.sh --self-test  # 検査そのものを検査する
tools/remote-check.sh --list       # 仕込める欠陥の一覧
tools/remote-check.sh --inject history-css   # 今回のバグを再現して赤を見る
```

中身は `tools/remote-check.js` (Node)。**`assets/remote/` は読むだけ**で、
1 バイトも書き換えない。

### 3-1. なぜ本物のブラウザなのか

今回のバグは **CSS のカスケード**だった。手で書いた DOM もどきや jsdom では
「どちらの規則が勝つか」の真実は出せない (jsdom は npm 依存も要る)。
Chromium 系を CDP で叩けば、**実物のエンジンの `getComputedStyle`** が答える
ので嘘が無い。

### 3-2. なぜ Node を使うのか (CLAUDE.md は Python を禁じている)

禁じている理由は「リポジトリに第 2 の言語と第 2 の実行環境が増える」ことだった。
ここで動かす対象は**そもそも JavaScript と CSS** である。JS を評価するのに
JS エンジンを使うのは、道具の言語を増やしているのではない。
そして Rust には JS も CSS も評価する手段が無い (エンジンを依存に足す話になる)。

**npm パッケージは 1 つも使わない。** WebSocket は握手とフレームだけ自前で
書いてあるので、`node_modules` も新しい Node も要らない (Node 18 以上)。

### 3-3. 何を見ているか — 「既知のバグ」ではなく**不変条件**

1. 見えている `.view` はいつでも**ちょうど 1 つ**
2. 1 つの `.view` の中で、場所を分け合う**主枠**が同時に 2 つ以上見えない
   ← 今回のバグはここに出る
3. 同じ親の子どうしの**矩形が重ならない**
4. **横にはみ出さない** (横スクロールを持たない入れ物で `scrollWidth` 超過なし)
5. 見えているボタンは**指で押せる大きさ**がある (0px の幽霊ボタンを作らない)
6. JS 例外・`console.error` が **1 件も出ない**
7. エージェント画面を開いている間、**ポーリングが実際に飛んでいる**
   (判定はページの中ではなく**偽 PC 側の受信数**で行う。ページの中の変数は
   いくらでも嘘をつく)
8. エージェントのチップを押したら、**端末の中身がそのエージェントへ変わる**
   (遡って追従を止めた状態から。止めないと**バグのある版でも緑になる**)

「主枠」は決め打ちの id ではなく **`flex-grow ≥ 1` か、ビューの 35% 以上の高さを
占める子**として拾う。だから `assets/remote/js/` に新しい画面を 1 枚足しても、
検査の側を書き換えずにそのまま見張られる。

### 3-4. 未知のバグをどう出すか

* **下部ナビとセグメントの順序つき総当たり** (2 手と 3 手)。
  順番を列挙するのが人ではないので、**誰も試していない順番**が出る。
  今回のバグは「一覧 → 端末」の 2 手目だった
* **面を選んだままタブを出て戻る**往復
* **乱歩** (チップ / カード / レーン見出しも混ぜる)。**種を固定**してあるので、
  落ちたら同じ `--seed` で必ず再現する
* **中身の 4 通り**: いちばん狭い端末 (320px) / エージェント 0 体の空状態 /
  訳が長い英語 / `/api/scrollback` を持たない旧 PC。
  空状態と別言語は、いちばん壊れやすいのに手では試されない

1 回の実行で **360 前後の状態**を確かめる。見た目が変わった状態だけ隅々まで
見る (同じ見た目を何百回も深掘りしない)。

### 3-5. 空振りしないことを毎回証明する (`--self-test`)

検査は「赤にできること」を示して初めて意味を持つ。`--self-test` は
**素の状態が緑**であることに加えて、7 つの欠陥を**その場で仕込んで**
(ディスクは書き換えない)、**全部捕まること**を確かめる。

| 仕込み | 何を再現するか | どの検査が捕まえるか |
|--------|----------------|----------------------|
| `history-css` | **0.18 で実際に出たバグ** (`#alist.mid`) | 主枠が 2 つ |
| `two-views` | `.view` が 2 つ同時に act | 見えているビュー数 |
| `overflow` | 幅の広い要素で横に見切れる | はみ出し |
| `dead-button` | 見えているのに押せないボタン | 当たり判定 |
| `no-poll` | ポーリングが 1 本も飛ばない | 偽 PC 側の受信数 |
| `chip-dead` | チップを押しても切り替わらない | 端末の中身が変わらない |
| `js-error` | 操作すると例外が飛ぶ (見た目は無事) | console |

`history-css` の実測 (仕込んだとき):

```
✗ 仕込み: history-css — 違反 40 件 (374 状態)
    [slot] #v-agent の主枠が同時に 2 個見えている: #scr, #alist   <- 面 2:0
    [slot] #v-agent の主枠が同時に 2 個見えている: #alist, #zv-appr <- 面 2:0→4
```

**この 1 行が出ていれば、あのバグは出荷されなかった。**

### 3-6. 見ていないもの (正直に)

* 実機の Safari / Chrome (エンジンは同系統だが同一ではない)。iOS 固有の
  `-webkit-overflow-scrolling` や safe-area の実挙動は見ていない
* 見た目の良し悪し。見ているのは**構造の不変条件**だけ
* PC 側 (`src/remote.rs`) の実装。API は偽物で応答するので、
  **本物と偽物がずれたら検査は嘘になる**。API の形を変えるときは
  `apiPayload` も直すこと (`--self-test` の `no-poll` / `chip-dead` が
  ずれに気付く網になっている)
* 実機のタッチ・IME・音声入力

## 4. ブラウザが無い環境の最後の砦 — CSS の法則を Rust で持つ

`tools/remote-check.sh` は node か Chromium が無ければ `[skip]` する。
そこで**今回のバグの形だけ**は、ブラウザ抜きで常に効く番人にしてある
(`src/cli.rs` の `mod tests`)。

```
#alist          { display:none;  }
#alist.show     { display:block; }   ← 見せる合図はこれ
#alist.mid      { display:flex;  }   ← 合図を経由せずに見えてしまう
```

法則にするとこうなる。

> **`display:none` で隠した要素を見せる規則たちは、クラス集合の包含で
> 1 本の鎖になっていなければならない。**

鎖なら「いちばん小さいもの = 見せる合図」が一意に決まり、他は必ずそれを含む。
枝分かれした瞬間、合図を通らない抜け道ができる。

* `assets/remote/style.css` と、**JS に埋め込まれた CSS**
  (`css.textContent = [...]` / テンプレートリテラル) の両方を見る
* 解析が壊れると永久に緑になるので、**土台を最低 N 個拾えたこと**も併せて
  確かめる (空振りの検出)
* `cli::tests::脇道の検査はわざと壊すと赤になる` が、直った形と壊れた形を
  両方通して**赤にできること**を毎回証明する

## 5. 増やし方

* **段を足す**: `tools/release-gate.sh` の `STEPS` に 1 語 + `desc_<名前>` +
  `run_<名前>()`。入口 (下半分) は触らない
* **スマホの不変条件を足す**: `tools/remote-check.js` の `pageDriver` の
  `check()` に 1 つ足し、**同時に `INJECTIONS` へ「それを破る仕込み」を足す**。
  仕込みの無い検査は、いつ空振りになったか分からない
* **判定行を必ず出す**: どのスクリプトも、どの経路で終わっても最後の 1 行に
  `✓ … 緑` / `✗ … 赤 (rc=N)` / 理由つきの `[skip]` を書く。
  `| head` を挟むと `$?` はそちらのものになるので、終了コードだけを真実に
  しない。番人は `cli::tests::検証スクリプトは終了時に判定行を出す`
