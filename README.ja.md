## なぜ Zaivern Code か

AI コーディング CLI を何本も起動するのは簡単ですが、把握し続けるのは大変です。
どのエージェントも別のタブに住み、それぞれの都合で承認を求め、他が何をしているかを
知らないままファイルを書き換えます。

<!-- 出典: docs/conflict-zero.md §3.3 — 書き手 64 / 重なり 0.5:
     ベースラインは 57/64 のマージが衝突し 132 ハンク、ガード側は全規模で 0 ハンク -->

| コックピットが無いとき | Zaivern Code |
|---|---|
| 並列度を上げるほどマージ衝突が増える | 共有台帳で担当行を分ける — 64 体で素の git が 132 ハンク出すところ、衝突ハンク 0 |
| 誰が待っているかタブを巡って探す | 全エージェントを 1 画面で、状態つきで見る |
| 同じ指示を各ツールへ貼り直す | 1 回でフリート全体へ送る／1 体だけを指名する |
| 承認待ちを見落として実行が止まる | 通知とワンクリック承認 |
| 動いている間はデスクを離れられない | スマホから進捗確認と承認 |

Zaivern Code は AI そのものではなく、AI も同梱しません。すでにインストールして
ログイン済みの CLI を動かす道具です。1 つあれば始められます。

## クイックスタート

**前提** — 対応する AI コーディング CLI を最低 1 つインストールしてログインしてください。
Claude Code・Codex・Gemini CLI を含む 33 種類の起動プリセットを収録しています。
1 つあれば足ります。

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/tacyan/zaivern-code/main/install.sh | sh
zai .
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/tacyan/zaivern-code/main/install.ps1 | iex
zai .
```

どちらのインストーラも、取得したアーカイブを**展開する前に**リリースの
`checksums.txt` と SHA-256 を突き合わせます。一致しない場合、あるいは
チェックサム自体を取得できなかった場合は、**展開も実行もせずに中止**します。

スクリプトをシェルへ流し込むのに抵抗がある場合は、
[Releases](https://github.com/tacyan/zaivern-code/releases/latest) から自分の環境向けの
アーカイブを取得し、展開した `zai`（Windows は `zai.exe`）を `PATH` 上に置いてください。
あとはプロジェクトのフォルダで `zai .` を実行します。手で検証する方法・ビルド来歴の
確認・SBOM については [SECURITY.md](SECURITY.md) を参照してください。

画面が開いたら:

1. `+ Agent` を押して、インストール済みの CLI を選ぶ
2. 入力欄へ作業内容を書いて送る
3. 慣れてきたら 2 体目を足す

### 更新する

```bash
zai update            # 最新版を確認し、実行するコマンドを見せてから更新
zai update --check    # 確認するだけ（何も実行しません）
zai update --yes      # 確認を求めずに更新する
```

`zai update` はエディタが起動していなくても使えます。お使いのプラットフォーム向けの
インストーラ経由で、その場で更新します。上のワンライナーを再実行しても同じことが
できます。

削除は `zai uninstall`（`--dry-run` で消える対象を一覧表示）。削除の対象は
実行ファイル本体と `~/.zaivern` だけで、`PATH` 上の別の `zai` は一覧に出すだけで
消しません。

## 主な機能

### 競合コーディネーション（これを作った理由）

これから編集するファイル（あるいは個々の行域）を、リポジトリごとの共有台帳で確保し、
ぶつかる書き込みを git フックが断ります。

<!-- 出典: docs/conflict-zero.md §3.8.1 — --layout disjoint / 64 体:
     B (ファイル単位の所有) 完了 1・拒否 63、Cref (行域) 完了 64・拒否 0・ハンク 0 -->
規模に耐えるかどうかは行域で決まります。1 つのファイルへ 64 体をぶつけると、
ファイル単位の確保では **1 体**しか通らず残り **63 体**が拒否されます。行域オーナーシップなら
**64 体全部**が通り、拒否は 0、それでいて統合後の衝突ハンクは **0** のままです。

<!-- 出典: docs/conflict-zero.md §3.12.2 — 錨の誤マッチによる二重配布と、その修正 -->
行域は行番号ではなく**錨**（先頭行と末尾行の中身）で追いかけるので、上の行が編集されても
生き残ります。取り直した錨が台帳の記録と違う場所に当たったときは、その読みを採りません。
確保が黙って別の場所へ移動することはない、ということです。

意味的な競合はこれでも拾えません。何を防げて何を防げないかは
[下の節](#競合コーディネーション)に書きます。

### Agent Cockpit

複数の AI CLI をタイル状に並べ、考え中・編集中・実行中・確認待ちのどれかをひと目で
把握できます。33 種類の起動プリセットを内蔵しているので、コマンドラインを思い出さずに
2 クリックでエージェントを足せます。

### ブロードキャスト

ひとつの入力欄から、動いている全エージェントへ同じ指示を送れます。1 体だけを選んで
指示することもできます。同じ訂正をフリート全体へ入れたいときに効きます。

### 状態・承認・通知

権限の確認待ち、停滞、予期しない終了を通知として拾い、ワンクリックで対処できます。
自動承認は既定でオフで、使うときは自分で明示的にオンにします。

### スマホリモート

スマホから進捗確認・指示・承認・ファイル編集ができます。いちばん簡単なのは同じ
Wi-Fi 内での利用で、そうでない場合は 2 つの経路が使えます。
**[Tailscale](https://tailscale.com/)** (PC とスマホが同じ tailnet に居るだけでよく、
踏み台は要りません) と、既に SSH で入れるホストを中継する SSH トンネルです。
経路を変えても**変わるのは待ち受け先だけ**で、トークンもポートもページも同じなので、
既に読み取った QR はそのまま使えます。

Tailscale モードは踏み台もポート開放も要りません。PC とスマホに
[Tailscale](https://tailscale.com/download) を入れて同じ tailnet にサインインし、
📱 の窓で **🔒 Tailscale で待ち受ける** を押すだけです。待ち受けるのは tailnet の
アドレスと `127.0.0.1` **だけ**なので、喫茶店や空港の Wi-Fi に居ても、その LAN からは
ポートが見えません。tailnet のアドレスはカーネルの経路表から引いており、
`tailscale` コマンドは実行しません — macOS のそれはデーモンに繋がらないと
**返ってこない**シェルラッパで、ぶら下がった子は UI を固めるためです。

### 内蔵エディタ

AI が変更した箇所をアプリから離れずに読めます。画像・PDF・CSV・Markdown も開けます。
未保存のまま落ちても本文は失われず、次の起動で書きかけが戻ります。その間にディスク側が
書き換わっていた場合は、黙って上書きせず差分を見せます。

## 競合コーディネーション

台帳の確保は助言ではありません。ぶつかる書き込みは、それを行おうとしたその瞬間に
フックが断ります。衝突はマージの段階ではなく、そこで表に出ます。

<!-- 出典: docs/conflict-zero.md §3.16.6 — dup_lines=0 は常に成立 (内容に依存しない)、
     conflict_files=0 は条件付き (帯 + 壁 + 昇順。反復的な内容では断ることがある) -->
成り立ち方の違う保証が 2 つあり、混ぜると言い過ぎになります。「同じ行を 2 人に配らない」は
台帳の性質なので、ファイルの中身に関係なく常に成り立ちます。「そのあとマージが一撃で通る」は
条件付きで、安全帯・2 つの域のあいだにある一意な行（壁）・昇順が要ります。反復的な内容では
前者が成り立ったまま後者だけが崩れるので、その場合ゲートは推測せずに断ります。

拾えないのは意味的な競合です。片方が関数のシグネチャを変え、もう片方が別のファイルで
古い呼び方のまま書く。マージは綺麗に通り、それでもコードは壊れています。

```console
$ zai czero init      # 台帳・git フック・マージドライバを入れて自己診断
$ zai czero verify    # 使い捨てのリポジトリで実際に競合を起こし、止まるかを確かめる
```

適用範囲・制約・その根拠となる実測は
[docs/conflict-zero.md](docs/conflict-zero.md) にあります。

## リソース使用量

<!-- 出典: docs/idle-cost.md §7 — 2026-08-15、同一マシン・同一セッションで
     Zed 1.15.0 / zai 0.16.0 / zai 0.17.0 を交互に 3 ラウンド、9/9 VALID。
     0.16.0 を陽性対照に入れてあるので「測定が生きていること」まで示せる。
     0.17.0 は測定床に張り付いているので必ず「≤」で書くこと -->

一日中開きっぱなしにするエディタは、打っていないあいだ何も食わないべきです。
同じマシン・同じセッションで、アプリを 3 回交互に入れ替えながら測りました
（macOS 26.5.2・電源接続・観測窓 180 秒・4 ファイルだけの中立なワークスペース）:

| | Zed 1.15.0 | Zaivern Code 0.17.0 |
|---|---:|---:|
| アイドル CPU（3 回の中央値） | 1 コアの 0.761% | **≤0.006%** — 測定床 |
| ダウンロード | 424.6 MB（`.app`） | **28.7 MB**（単一バイナリ） |
| RSS | 162.2 MB | 170.3 MB |

この表が気をつけている点が 2 つあります:

- **`≤0.006%` は読み取った値ではなく床です。** `ps` は CPU 時間を 1/100 秒までしか
  分解しないので、180 秒の窓ではそれ未満を区別できません。3 回とも**ちょうど 1 目盛**
  でした。正直に言えるのは「Zed より 127 倍以上低い」であって、比そのものではありません。
- **RSS は勝っていませんし、勝ったとも書きません。** Zed も Rust 製で、両者の差は 5%
  以内 = 誤差です。桁で違うのはダウンロードサイズのほうです。

同じ実行で Zaivern Code **0.16.0** は 8.933% でした。これが陽性対照です。同じセッションで
高い値を出す版が無ければ、ほぼゼロという結果は**測定が壊れている**のと見分けが付きません。
0.17.0 でアイドルが落ちたのは、ガイドツアーが無条件にコマを予約するのをやめ、2 秒ごとの
掃除の再描画を無くしたためです。

再現は `tools/idle-duel.sh --vs Zed --out /tmp/duel.tsv`。このハーネスは**正直に測れない
ときは測りません** — pid で最前面かを確かめ、マシンが無操作であることを要求し、根拠を
毎行に記録します。手順・生の数値・踏んだ罠は [docs/idle-cost.md](docs/idle-cost.md) に
あります。

## 対応環境

| 項目 | 対応内容 |
|---|---|
| OS | macOS arm64/x86_64・Linux x86_64/arm64・Windows x86_64 |
| AI CLI | Claude Code・Codex・Gemini CLI ほか、33 種類の起動プリセット |
| Rust | 1.88 以上 — ソースからビルドするときのみ |
| ライセンス | Apache-2.0 |

Claude Code が実装し、Codex がテストし、Gemini CLI がドキュメントを書く、というのは
よくある構成の一例で、Zaivern Code はその分担を前提にしていません。どの組み合わせでも、
1 体だけでも動きます。

## 安全設計

- 承認必須が既定。自動 YES はセッションごとに明示的に有効化します
- 権限昇格は常に手動承認です
- MCP の環境変数は値を表示せず、設定済みかどうかだけを出します
- セッション破棄時とアプリ終了時に子プロセスを停止し、孤児プロセスを残しません

## よくある質問

**tmux でペインを分割するのと何が違いますか？**

tmux は端末を並べますが、その中で何が起きているかは知りません。Zaivern Code は各
エージェントの状態を読むので、どれが考え中で、どれが編集中で、どれが承認待ちで止まって
いるかを出せますし、その承認要求を通知に変えてワンクリックで返せます。tmux に対応物が
無いのは共有台帳のほうです。2 体が同じ行へ物理的に書けません — ぶつかる 2 つ目の書き込みは
マージまで持ち越されず、書こうとしたその瞬間に git フックが断ります。

**共有台帳のぶんだけ遅くなりませんか？**

<!-- 出典: docs/conflict-zero.md §1「意味しないこと」4 / §3.3 (掃引: 4〜8 体 p50 40〜50ms、
     64 体 p50 160ms、busy-deny 32 体 4 件・64 体 14 件) / §3.4 (ゲート 1536 回で p50 298.7ms)。
     体数だけでは決まらないので、必ず担当表の大きさを添えること -->
遅くなります。しかも規模が上がるほど効きます（ゲートが書き込みの経路に居るため）。標準の
掃引（書き手 N・ファイル N×6）で、4〜8 体は p50 40〜50ms、64 体で p50 160ms。**効くのは
体数だけではありません** — ゲートを 1536 回呼ぶ重い担当表なら、同じ 64 体でも p50 298.7ms
まで伸びます。「64 体で何 ms」という 1 つの数字は、担当表の大きさを添えないと足りません。
さらに 32 体以上では、時間内に判定しきれないときに `busy-deny` が出ます。推測せずに断る側へ
倒した結果で、再試行すれば通りますが、利用者からは「たまに拒否される」として見えます。
1〜2 体なら、ゲートは臨界路に居ません。

**「競合ゼロ」は結局どこまでを指しますか？**

言葉の見た目より狭く、意図的にそうしています。

<!-- 出典: docs/conflict-zero.md §3.2 (書き手 8 / 重なり 1.00: 10/48 成立・38 件をゲートが停止)、
     §3.8.1 (disjoint / 64 体: 素の git のハンクは全規模 0。B は完了 1、Cref は 64)、§3.16.6 -->
- **ゼロは書き込みを断って買っています。** 8 人が同じファイル群を狙う条件では、計画した
  48 件のうち書けたのは 10 件で、残り 38 件はゲートが止めました。衝突数は 0 ですが、
  通った量は 0 ではありません。
- **十分に離れた行域は、もともと助けが要りません。** 素の git がそのまま 0 件でマージします。
  行域オーナーシップは git にできないことをしているのではなく、**ファイル単位の確保が
  壊した並列度を戻している**だけです（64 体中 1 体 → 64 体中 64 体）。
- **2 つの保証は同じ強さではありません。** 「同じ行を 2 人に配らない」は常に成り立ち、
  「マージが一撃で通る」は条件付きで、反復的な内容では崩れます。

[docs/conflict-zero.md](docs/conflict-zero.md) は、この線引きから始めて、支える実測を
（後から反証された主張も含めて）全部載せています。
