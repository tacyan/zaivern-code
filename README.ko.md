## Zaivern Code가 필요한 이유

AI 코딩 CLI를 여러 개 띄우는 것은 쉽습니다. 어려운 것은 계속 파악하는 일입니다.
모든 에이전트는 각자의 터미널 탭에 살면서, 각자의 속도로 승인을 요구하고,
다른 에이전트가 무엇을 하는지 모른 채 파일을 고칩니다.

<!-- 출처: docs/conflict-zero.md §3.3 — 작성자 64 / 겹침 0.5:
     베이스라인은 57/64의 머지가 충돌하며 132 헝크, 가드 측은 모든 규모에서 0 헝크 -->

| 조종석이 없을 때 | Zaivern Code가 있을 때 |
|---|---|
| 병렬 에이전트를 늘릴수록 머지 충돌이 늘어난다 | 공유 원장이 에이전트를 서로의 행에서 떼어놓는다 — 순정 git이 132 헝크를 내는 64 에이전트 조건에서 충돌 헝크 0 |
| 누가 나를 기다리는지 탭을 돌며 찾는다 | 모든 에이전트를 한 화면에서, 실시간 상태와 함께 |
| 같은 지시를 도구마다 붙여넣는다 | 한 번에 플릿 전체로 방송하거나, 한 에이전트만 지정 |
| 승인 요청을 놓쳐서 실행을 날린다 | 알림과 원클릭 승인 |
| 에이전트가 일하는 동안 자리를 못 뜬다 | 휴대폰에서 진행 확인과 승인 |

Zaivern Code는 AI 모델이 아니며, AI 모델을 동봉하지도 않습니다. 이미 설치하고
로그인해 둔 CLI를 구동하는 도구입니다 — 하나만 있어도 시작할 수 있습니다.

## 빠른 시작

**사전 준비.** 지원되는 AI 코딩 CLI를 최소 하나 설치하고 로그인하세요.
Zaivern Code는 Claude Code, Codex, Gemini CLI를 포함해 33종의 실행 프리셋을 내장하고
있습니다. 두 개 이상 필요하지 않습니다.

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/tacyan/zaivern-code/main/install.sh | sh
zai .
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/tacyan/zaivern-code/main/install.ps1 | iex
zai .
```

두 설치 스크립트 모두 릴리스 아카이브를 **압축 해제하기 전에** 공개된 `checksums.txt`와
대조합니다. SHA-256이 일치하지 않거나, 애초에 체크섬을 가져올 수 없는 경우에는
아무것도 풀거나 실행하지 않고 중단합니다.

셸에 스크립트를 흘려 넣는 것이 꺼려진다면,
[Releases](https://github.com/tacyan/zaivern-code/releases/latest)에서 자신의 플랫폼용
아카이브를 내려받아 압축을 풀고, `zai`(또는 `zai.exe`)를 `PATH` 위의 어딘가에 두세요.
그다음 프로젝트 폴더에서 `zai .` 를 실행합니다. 내려받은 파일을 직접 손으로 검증하는
방법, 빌드 프로버넌스 확인, SBOM 열람은 [SECURITY.md](SECURITY.md)를 보세요.

창이 열리고 나면:

1. `+ Agent` 를 눌러 이미 설치해 둔 CLI를 고릅니다.
2. 입력란에 작업 내용을 적고 보냅니다.
3. 첫 번째가 익숙해지면 두 번째 에이전트를 추가합니다.

### 업데이트

```bash
zai update            # 새 릴리스를 확인하고, 실행할 명령을 보여준 뒤 업그레이드
zai update --check    # 확인만 하고 아무것도 바꾸지 않음
zai update --yes      # 확인 프롬프트 없이 업그레이드
```

`zai update`는 에디터가 실행 중이든 아니든 동작하며, 플랫폼에 맞는 설치 스크립트를
통해 그 자리에서 업그레이드합니다. 위의 원라이너를 다시 실행해도 같은 일을 합니다.

`zai uninstall`은 제거합니다(`--dry-run`으로 지워질 대상을 나열). 제거 대상은
실행 파일과 `~/.zaivern`뿐이며, `PATH` 위의 다른 것들은 목록에 보여줄 뿐 절대
삭제하지 않습니다.

## 표시 언어

기본으로 들어 있는 언어는 **English · 日本語 · 简体中文 · 한국어 · Português (Brasil) ·
Español** 여섯 가지이고, 전환에 **재시작은 필요 없습니다**. 고른 다음 프레임부터 화면
전체가 바뀝니다.

입구는 툴바의 🌐 메뉴, 메뉴 바의 "보기 → 표시 언어", 명령 팔레트, 설정 화면의
"외관"입니다. 어디에서 바꾸든 `~/.zaivern/config.toml`의 `ui_language`로 모이며,
기본값 `"auto"`는 OS의 언어를 따릅니다.

들어 있지 않은 언어는 앱을 다시 빌드하지 않고 GitHub에서 설치할 수 있습니다.

```sh
zai lang list --remote        # 배포처에 있는 언어 팩 보기
zai lang install zh-CN
zai lang set zh-CN
zai lang install fr --from someone/zaivern-lang-fr
```

직접 만들 때는 `zai lang export fr`로 `~/.zaivern/locales/fr.json`에 서식을 써 내고,
편집한 뒤 `zai lang check fr`로 과부족을 검사하고 `zai lang set fr`. **기본 제공과 같은
ID를 한 줄만 쓰면 그 한 줄만 덮어쓸 수 있습니다.** 한 단어를 고치려고 사전을 통째로
들고 있을 필요는 없습니다.

자세한 내용은 [docs/i18n.md](docs/i18n.md)에 있습니다.

## 주요 기능

### 충돌 조정 (이 프로젝트가 존재하는 이유)

에이전트는 앞으로 편집할 파일 — 또는 개별 행 범위 — 을 저장소별 공유 원장에 확보하고,
충돌하는 쓰기는 git 훅이 거부합니다.

<!-- 출처: docs/conflict-zero.md §3.8.1 — --layout disjoint / 64체:
     B (파일 단위 소유) 완료 1·거부 63, Cref (행 범위) 완료 64·거부 0·헝크 0 -->
규모에서 쓸 만해지는 이유는 행 범위입니다. 64개의 에이전트를 한 파일로 겨누면
파일 단위 리스는 정확히 **1개**만 통과시키고 나머지 **63개**를 거부합니다.
행 범위 오너십이라면 **64개 전부**가 통과하고, 거부는 하나도 없으며, 그러고도 머지는
여전히 충돌 헝크 **0**을 냅니다.

<!-- 출처: docs/conflict-zero.md §3.12.2 — 앵커 오매칭에 의한 이중 배분과 그 수정 -->
행 범위는 행 번호가 아니라 **앵커**(첫 행과 마지막 행의 내용)로 추적하므로, 그 위쪽이
편집되어도 살아남습니다. 앵커를 다시 해석한 결과가 원장에 기록된 것과 다른 곳에
걸리면, 그 읽기를 신뢰하지 않고 버립니다. 확보가 조용히 파일의 다른 부분으로
옮겨가는 일은 없다는 뜻입니다.

이것으로도 의미적 충돌은 잡지 못합니다. 무엇이 범위 안이고 무엇이 밖인지는
[아래 절](#충돌-조정)에 적어 두었습니다.

### Agent Cockpit

여러 AI CLI를 타일처럼 나란히 놓고, 어느 것이 생각 중이고, 편집 중이고, 실행 중이고,
나를 기다리는지 한눈에 봅니다. 33종의 실행 프리셋을 내장하고 있어서 에이전트를 추가하는
일은 명령줄을 떠올리는 대신 두 번의 클릭으로 끝납니다.

### 브로드캐스트

하나의 입력란에서 실행 중인 모든 에이전트에게 같은 지시를 보내거나, 집중해서 다루고
싶을 때는 한 에이전트만 고릅니다. 같은 정정을 플릿 전체에 적용할 때 유용합니다.

### 상태, 승인, 알림

Zaivern Code는 권한 프롬프트, 정체, 예기치 않은 종료를 원클릭으로 대응할 수 있는
알림으로 드러냅니다. 자동 승인은 기본적으로 꺼져 있고, 쓰려면 의도적으로 켜야 합니다.

### 폰 리모트

휴대폰에서 진행 상황 확인, 지시 전송, 작업 승인, 파일 편집을 할 수 있습니다.
가장 간단한 구성은 같은 Wi-Fi 네트워크에서 쓰는 것이고, 그렇지 않을 때는 두 가지
전송 경로 중 하나가 이어받습니다. 두 기기가 이미 같은 tailnet에 있다면
**[Tailscale](https://tailscale.com/)**, 아니면 이미 접속할 수 있는 호스트를 거치는
SSH 터널입니다. 전송 경로를 바꿔도 **바뀌는 것은 서버가 대기하는 위치뿐**이고
토큰, 포트, 페이지는 그대로이므로, 휴대폰에서 이미 스캔한 QR은 계속 동작합니다.

Tailscale 모드는 배스천도 포트 포워딩도 필요 없습니다. PC와 휴대폰에
[Tailscale](https://tailscale.com/download)을 설치하고 둘 다 같은 tailnet에 로그인한 뒤,
폰 리모트 창에서 **🔒 Tailscale로 대기** 를 누르면 됩니다. tailnet 주소와 `127.0.0.1`
**만** 바인딩하고 그 밖에는 아무것도 열지 않으므로, 지금 접속해 있는 카페나 공항
Wi-Fi에서는 포트 자체가 보이지 않습니다. Zaivern은 tailnet 주소를 커널 라우팅
테이블에서 찾으며 `tailscale` 명령을 실행하지 않습니다 — macOS의 그 CLI는 데몬에
닿지 않을 때 영원히 멈출 수 있는 셸 래퍼이고, 멈춘 자식 프로세스는 UI를 얼리기
때문입니다.

### 내장 에디터

앱을 벗어나지 않고 코드를 읽고, 에이전트가 무엇을 바꿨는지 검토할 수 있습니다.
이미지, PDF, CSV, Markdown도 포함됩니다. 저장하지 않은 버퍼는 크래시를 견딥니다.
다음 실행에서 복원되며, 그사이 디스크의 파일이 바뀌었다면 조용히 덮어쓰지 않고
차이를 보여줍니다.

## 충돌 조정

원장의 확보는 권고가 아닙니다. 훅은 충돌하는 쓰기를 시도한 바로 그 순간에 거부하므로,
충돌은 머지 시점이 아니라 그 자리에서 드러납니다.

<!-- 출처: docs/conflict-zero.md §3.16.6 — dup_lines=0 은 항상 성립 (내용에 의존하지 않음),
     conflict_files=0 은 조건부 (안전대 + 벽 + 오름차순. 반복적인 내용에서는 거부할 수 있음) -->
성립하는 방식이 다른 두 개의 보증이 있고, 이를 섞으면 과장이 됩니다.
"같은 행을 두 에이전트에게 나눠 주지 않는다"는 원장의 성질이므로 파일의 내용과 무관하게
항상 성립합니다. "그다음 머지가 한 번에 통과한다"는 조건부입니다. 안전대(safety band),
두 범위 사이에 있는 고유한 행, 그리고 오름차순이 필요합니다. 반복적인 내용은 앞의 것이
성립한 채로 뒤의 것만 무너뜨릴 수 있고, 그런 경우 게이트는 추측하지 않고 거부합니다.

잡지 못하는 것은 의미적 충돌입니다. 한 에이전트가 함수 시그니처를 바꾸는 동안
다른 에이전트가 다른 파일에서 옛 방식으로 계속 호출하고, 머지는 완벽하게 깨끗한 경우입니다.

```console
$ zai czero init      # 원장, git 훅, 머지 드라이버를 설치하고 자가 진단
$ zai czero verify    # 일회용 저장소에서 실제로 충돌을 일으켜 막히는지 확인
```

적용 범위, 한계, 그 근거가 되는 실측은
[docs/conflict-zero.md](docs/conflict-zero.md)에 있습니다.

## 리소스 사용량

<!-- 출처: docs/idle-cost.md §7 — 2026-08-15, 같은 머신·같은 세션에서
     Zed 1.15.0 / zai 0.16.0 / zai 0.17.0 을 번갈아 3 라운드, 9/9 VALID.
     0.16.0 을 양성 대조로 넣어 두었으므로 "측정이 살아 있음"까지 보일 수 있다.
     0.17.0 은 측정 바닥에 붙어 있으므로 반드시 "≤" 로 쓸 것 -->

하루 종일 열어 두는 에디터는, 타이핑하지 않는 동안 아무것도 소모하지 않아야 합니다.
같은 머신에서 한 세션 동안 앱을 세 번 번갈아 가며 측정했습니다
(macOS 26.5.2, 전원 연결, 180초 관측 창, 파일 4개짜리 중립 워크스페이스):

| | Zed 1.15.0 | Zaivern Code 0.17.0 |
|---|---:|---:|
| 유휴 CPU (3회 중앙값) | 1 코어의 0.761% | **≤0.006%** — 측정 바닥 |
| 다운로드 | 424.6 MB (`.app`) | **28.7 MB** (단일 바이너리) |
| RSS | 162.2 MB | 170.3 MB |

이 표가 조심하고 있는 점이 두 가지 있습니다:

- **`≤0.006%`는 읽어낸 값이 아니라 바닥입니다.** `ps`는 CPU 시간을 1/100초까지만
  분해하므로 180초 창에서는 0.006% 미만을 구별할 수 없습니다. 세 라운드 모두 정확히
  한 틱에 걸렸습니다. 정직하게 말할 수 있는 것은 "Zed보다 최소 127배 낮다"이지,
  특정한 비율이 아닙니다.
- **RSS는 이긴 것이 아니고, 이겼다고 주장하지도 않습니다.** Zed 역시 Rust로 작성되어
  있고, 둘의 차이는 5% 이내 = 노이즈입니다. 자릿수가 다른 것은 다운로드 크기 쪽입니다.

같은 실행에서 Zaivern Code **0.16.0**은 8.933%로 측정되었습니다 — 이것이 양성 대조입니다.
같은 세션에서 높은 값을 내는 버전이 없다면, 0에 가까운 결과는 **측정이 망가진 것**과
구별할 수 없습니다. 0.17.0에서 유휴 비용이 떨어진 이유는 가이드 투어가 더 이상
무조건 프레임을 예약하지 않고, 2초마다 돌던 정리용 재그리기가 사라졌기 때문입니다.

재현은 `tools/idle-duel.sh --vs Zed --out /tmp/duel.tsv`. 이 하네스는 **정직하게 측정할
수 없을 때는 측정하지 않습니다** — pid로 앱이 최전면인지 확인하고, 머신이 조작되지 않은
상태일 것을 요구하며, 근거를 모든 행에 기록합니다. 전체 방법, 원본 수치, 우리가 밟은
함정은 [docs/idle-cost.md](docs/idle-cost.md)에 있습니다.

## 지원 환경

| 항목 | 지원 내용 |
|---|---|
| OS | macOS arm64/x86_64, Linux x86_64/arm64, Windows x86_64 |
| AI CLI | Claude Code, Codex, Gemini CLI를 포함한 33종의 실행 프리셋 |
| Rust | 1.88+ — 소스에서 빌드할 때만 |
| 라이선스 | Apache-2.0 |

Claude Code가 구현하고, Codex가 테스트하고, Gemini CLI가 문서를 쓰는 구성이 흔하지만,
Zaivern Code의 어떤 부분도 그 분담을 전제하지 않습니다. 어떤 조합이든, 에이전트 하나만
있어도 동작합니다.

## 안전 설계

- 승인 필수 모드가 기본값이며, Auto-YES는 세션마다 직접 켜야 합니다.
- 권한 상승은 언제나 수동 승인이 필요합니다.
- MCP 환경 변수의 값은 절대 표시하지 않고, 설정되어 있는지 여부만 보여줍니다.
- 세션이 파기되거나 앱이 종료될 때 자식 프로세스를 정지시키므로, 고아가 된 에이전트가
  뒤에서 계속 돌아가는 일이 없습니다.

## 자주 묻는 질문

**tmux로 페인을 분할하는 것과 무엇이 다른가요?**

tmux는 터미널을 나란히 놓을 뿐, 그 안에서 무엇이 돌아가는지는 전혀 모릅니다.
Zaivern Code는 각 에이전트의 상태를 읽으므로, 어느 것이 생각 중이고, 편집 중이고,
승인 프롬프트에서 막혀 있는지 보여줄 수 있으며, 그 프롬프트를 원클릭으로 답하는
알림으로 바꿉니다. tmux에 대응물이 없는 것은 공유 원장 쪽입니다. 두 에이전트는 물리적으로
같은 행에 쓸 수 없습니다 — 두 번째 쓰기는 머지까지 미뤄지지 않고, 시도한 바로 그 순간에
git 훅이 거부하기 때문입니다.

**리스 원장 때문에 느려지지 않나요?**

<!-- 출처: docs/conflict-zero.md §1「의미하지 않는 것」4 / §3.3 (스윕: 4~8체 p50 40~50ms,
     64체 p50 160ms, busy-deny 32체 4건·64체 14건) / §3.4 (게이트 1536회에서 p50 298.7ms).
     에이전트 수만으로 정해지지 않으므로 반드시 담당표의 크기를 함께 적을 것 -->
느려집니다. 게이트가 쓰기 경로 위에 있으므로 규모가 커질수록 더 심해집니다. 표준 스윕
— 작성자 N명이 N×6개의 파일을 다루는 조건 — 에서 게이트 지연은 4~8 에이전트일 때
p50 40–50 ms, 64일 때 p50 160 ms입니다. 에이전트 수만이 변수는 아닙니다. 게이트를
1536회 호출하는 더 무거운 담당표라면 같은 64 에이전트에서도 p50 298.7 ms에 이르므로,
"64 에이전트에서 X가 든다"는 단일 숫자는 작업량의 크기를 곁들이지 않으면 불완전합니다.
32 에이전트 이상에서는 시간 안에 판정하지 못할 때 게이트가 `busy-deny`로 답하기 시작합니다.
추측하는 대신 거부하는 쪽이고, 재시도하면 통과하지만, 사용자에게는 가끔 거부되는 것으로
보입니다. 에이전트가 하나나 둘이라면 게이트는 임계 경로에 있지 않습니다.

**"충돌 제로"는 실제로 무엇을 뜻하나요?**

들리는 것보다 좁은 의미이며, 의도적으로 그렇게 두었습니다:

<!-- 출처: docs/conflict-zero.md §3.2 (작성자 8 / 겹침 1.00: 10/48 성립·38건을 게이트가 정지),
     §3.8.1 (disjoint / 64체: 순정 git의 헝크는 모든 규모에서 0. B는 완료 1, Cref는 64), §3.16.6 -->
- **제로는 쓰기를 거부해서 산 것입니다.** 여덟 명의 작성자가 모두 같은 파일들을 겨누는
  조건에서, 계획된 48건의 편집 가운데 10건이 쓰였고 나머지 38건은 게이트에서 멈췄습니다.
  충돌 수는 0이지만, 처리량은 0이 아닙니다.
- **충분히 멀리 떨어진 행 범위는 애초에 도움이 필요 없었습니다.** 순정 git이 이미 그런
  경우를 충돌 0으로 머지합니다. 행 범위 오너십은 git이 못 하는 일을 하는 것이 아니라,
  **파일 단위 리스가 파괴한 병렬성을 돌려주는 것**입니다 (64 중 1 통과 대 64 중 64 통과).
- **두 보증의 강도는 같지 않습니다.** "같은 행을 두 에이전트에게 주지 않는다"는 항상
  성립하고, "머지가 한 번에 통과한다"는 조건부이며 반복적인 내용에서는 무너질 수 있습니다.

[docs/conflict-zero.md](docs/conflict-zero.md)는 바로 이 경계선에서 시작해, 그 뒤를
받치는 모든 실측을 (나중에 반증된 주장까지 포함해) 싣고 있습니다.

## 기여하기

버그 리포트, 기능 요청, 풀 리퀘스트를 환영합니다. 새로 등록하기 전에

```bash
git clone https://github.com/tacyan/zaivern-code.git
cd zaivern-code
rustup update stable
cargo run --release -- .
```

나머지는 [CONTRIBUTING.md](CONTRIBUTING.md)에 있습니다. 변경을 검증하는 방법, Linux와
Windows 검사를 로컬에서 돌리는 방법, 이 저장소가 따르는 관례를 다룹니다.
