## あなたのボトルネックは、もう「書く速度」ではない

Claude Code に実装を任せ、Codex にテストを書かせ、Gemini CLI にドキュメントを整えさせる——そんな開発は、もう未来の話ではありません。けれど今、あなたの手元にあるのは、散らばったターミナルのタブだけ。

- どのエージェントが動いていて、どれが止まっているのか、一目では分からない
- 承認待ちのまま 30 分放置されていた Claude Code。気づいた瞬間の、あの脱力感
- 同じ指示を 3 つのタブに 3 回ペーストする、無意味な往復

エージェントは疲れません。文句も言いません。**待たせているのは、いつも人間の側です。**

Zaivern Code は、この「指揮の摩擦」を消すために生まれました。すべてのエージェントを一望し、一言で全軍に命じ、呼ばれたら 1 クリックで応える。あなたはコードを「書く人」から、開発を**「指揮する人」**になります。

## 🚀 30秒で操縦席へ

**macOS / Linux** — ビルド済みバイナリを自動取得(無ければソースからビルド):

```bash
curl -fsSL https://raw.githubusercontent.com/tacyan/zaivern-code/main/install.sh | sh
```

**Windows** — PowerShell(同じ挙動: ビルド済みバイナリを自動取得し、取れなければソースからビルド。Rust が無ければ rustup ごと導入):

```powershell
irm https://raw.githubusercontent.com/tacyan/zaivern-code/main/install.ps1 | iex
```

インストールが終わったら、開きたいプロジェクトのフォルダで `zai .` と打つだけ——そこがあなたの操縦席になります(`zai [ワークスペースのパス]` でも指定可)。**同じワンライナーをもう一度実行すれば、最新版へ更新されます。** 各 OS のビルド済みバイナリは [**Releases**](https://github.com/tacyan/zaivern-code/releases/latest) から直接ダウンロードもできます(macOS arm64/x86_64・Linux x86_64/arm64・Windows x86_64)。

インストーラは同時に OS の**アプリ一覧にも「Zaivern Code」を登録**します——macOS は Launchpad / Spotlight、Linux はアプリメニュー、Windows はスタートメニューから、ターミナルを開かずに起動できます(ホームディレクトリがワークスペースになります)。手動での登録・解除は `zai app install` / `zai app uninstall`。プロセス一覧でも「Zaivern」で見つかります(macOS のアクティビティモニタ / `pgrep -i zaivern`、Windows のタスクマネージャー、Linux の `ps`)。
初回起動時は **26 手順のガイドツアー**が立ち上がり、計器のある場所を実際に光らせながら一巡します(所要 2 分ほど)。Esc かスキップでいつでも抜けられ、あとから 💡 メニューやコマンドパレットの「チュートリアルを再開」で見直せます。

## 🆕 v0.5.1 — 起動しただけで画面が動かない

- **セッション一覧は「このフォルダの会話」だけ** — ブランチ (worktree) 別にまとめる表示をやめました。同じフォルダを開いている限り一覧は常に同じです (VS Code の Claude Code 拡張と同じ切り方)。
- **起動しても何も立ち上がりません** — 前回のエージェントタブの自動復元を既定オフに。過去の会話へ戻る口は「💬 セッション」タブ (明示的に選んで再開) の 1 本に絞りました (`restore_agents = true` で従来動作)。
- **フリート看板が全画面に** — 下部パネル (既定 300px) の中のタブだったのをやめ、Cockpit / デッキと同格の中央ビューにしました。8 レーンが画面の 1/3 に潰れません。

## 操縦席から見える景色

### 🎛 全軍を、一望する — Agent Cockpit

ツールバーの **🎛 Cockpit** を押した瞬間(ショートカットは ⌘⇧C)、走っているすべてのエージェントがグリッドに並びます。各セルは飾りのプレビューではなく、**そのまま打ち込めるライブターミナル**。Claude Code が実装を進め、Codex がテストを直し、Gemini CLI がドキュメントを書く——5体が同時に手を動かす画面をはじめて見たとき、少し鳥肌が立つはずです。

そして Cockpit を開いたままファイルを開けば、**左にエディタ・右に Cockpit** の分割表示になります(境界はドラッグで調整可、MD/HTML プレビューも有効)。コードを読みながら、全軍を視界に入れたまま。

### 📣 一言で、全員に命じる — ブロードキャスト

「テストが通ることを確認して」「その方針で OK、続行」——1つの入力欄から、稼働中の全セッションへ同時送信。タブを渡り歩いて同じ文章をペーストして回る夜は、今日で終わりです。

### 🛡 手綱は、常にあなたの手に — 3つの権限モード

攻めるときは **⚡全自動**:各 CLI の bypass フラグを自動付与します。守るときは **🛡承認**:コマンドに紛れ込んだ bypass 系フラグを自動で取り除き、安全側に倒します。プリセットの記述をそのまま尊重する **👾Agent優先** も。ツールバーからワンクリックで切替、実行中のセッションにも一括送信できます。

bypass でも残る対話プロンプト(初回警告・フォルダ信頼確認・プラン承認など)への自動応答は、独立したスイッチ **「⚡ 自動YES」**(🐾 メニュー / `pet_auto_yes`)に分けてあります。**既定はオフ——承認は、必ずあなたを待ちます。** オンにすれば画面テキストを検知して自動応答し、どの権限モードで起動したセッションにも効きます。応答は **1つのプロンプトにつき1回だけ**。会話ログに映った「(y/n)」への誤爆も、Enter の連打もしません。

#### 💡 プロジェクト／グローバルでの自動YES（Auto-Approve）ルールの配置
エージェント（Antigravity や Claude Code など）自体に自律進行・自動YESのルールを永続化させる場合、以下の設定ファイルを配置できます。

- **プロジェクト単位**（該当フォルダ直下の `.gemini/rules.md`）:
  ```bash
  mkdir -p .gemini && cat << 'EOF' > .gemini/rules.md
  # Auto-Approve Settings
  - ツール実行やコマンド実行は確認待ちをせず、自動YES（Auto-Approve）で自律的に進行すること。
  - ファイル変更時は差分（Diff）を明示すること。
  EOF
  ```
- **全プロジェクト共通（グローバル）**（`~/.gemini/rules.md`）:
  ```bash
  mkdir -p ~/.gemini && cat << 'EOF' > ~/.gemini/rules.md
  # Global Auto-Approve Settings
  - 全プロジェクトにおいて、確認待ちをせず自動YES（Auto-Approve）で自律進行すること。
  - ファイル変更時は差分（Diff）を明示すること。
  EOF
  ```

**速さと安全は、二者択一ではありません。**

### 🔔 呼ばれたら、必ず気づく — 通知と、相棒の🐾ザイガニ

エージェントが承認を求めた瞬間——ポップアップが出て、効果音が鳴り、セッションの●が黄色に変わり、そして画面の隅を歩くデスクトップペット「**ザイガニ**」が「❗承認待ち」とそわそわし始めます。頭上に浮かぶバブルから **✔承認 / ✖拒否** をワンクリック。成功すれば🎉とジャンプし、失敗すれば💥とバツ目になる。

冷たいログを監視するのではなく、**相棒が肩を叩いてくれる**。エージェントを一秒も待たせない開発は、想像よりずっと気持ちがいいものです。

### 📱 席を立っても、指揮は続く — スマホリモート

トップバーの 📱 から QR コードを読むだけで、同じ Wi-Fi 内のスマホがリモコンになります。ソファから、ベランダから、コーヒーを淹れながら——承認も、指示出しも、ファイル編集も、進捗確認も。**エージェントが働いている間、あなたが机に縛られる理由はもうありません。**(起動ごとのランダムトークン認証・LAN 内のみ)

**Windows は、ここで一度だけ許可が要ります。** OS の既定が「受信はすべてブロック」なので、規則が無いとスマホからの接続は Windows に落とされます——PC 側は待ち受けていて QR も正しいのに、スマホだけ何も起きない。原因が画面のどこにも出ないので、以前は「Windows ではスマホから使えない」で終わっていました。いまは 📱 の画面が受信許可の有無を自分で調べ、無ければ理由を書いて **「🛡 受信を許可する」ボタン**を出します(管理者の確認が 1 回出るだけ)。許可するのは **この実行ファイルの TCP 8899-8919 だけ**で、取り消しも同じ画面から。ターミナルからは `zai firewall status` / `zai firewall allow` / `zai firewall revoke`。

### 🎤 話すだけで、指示が書ける — マイクボタンひとつの音声入力

**🎤 を押す。それだけ**です。あとは話した内容が、エージェントの入力欄に流れ込み続けます。押しっぱなしのキーも、覚えるショートカットも、別ウィンドウのブラウザも要りません。止めたくなったら、隣の **⏹ を押す**まで動き続けます。

大事なのは、**そこで止まる**こと。音声はよく誤認識します。だから Zaivern は Enter を送りません。入力欄に入った文字を目で見て、直したければ直して、納得してから自分で Enter を押す。**声は速く、送信は慎重に。**

そして **Enter で入力欄が空になっても、録音は続いたまま**です。送った次の瞬間にはもう次の指示を話し始められる——考えるリズムが途切れません。

- 届け先は **🎯 アクティブなエージェント** か **📣 全エージェント**。録音したまま切り替えられます
- 「アクティブ」を選んでおけば、タブを移った先へ自動的についてきます
- 「送信」などの合図キーワードを設定すれば、その言葉で終えたときだけ Enter まで送ります(既定はオフ = 常に手動)
- 言語・エンジンはトップバー 🎤 の隣の ▾ メニューから変更できます

そして音声入力は、**どの OS でも使えます**。何を使うかは `voice_engine = "auto"` が勝手に決めるので、あなたは 🎤 を押すだけです。

| 環境 | 押したときに動くもの |
|---|---|
| **macOS** | OS 内蔵の音声認識。オフラインで完結します |
| **Windows** | Windows 標準の音声認識(オフライン)。ただし**対応言語の認識器が入っているときだけ**です — 日本語の認識器は日本語版 Windows にしか同梱されず、Win11 24H2 でこの機能自体が非推奨になりました。起動時に実際に探しに行き、見つからなければ下のブラウザ経路へ静かに切り替わります |
| **Linux / 認識器のない Windows** | ローカルの音声入力ページ(`http://127.0.0.1:<port>/voice`)が開き、**ブラウザのマイク**で話します。Chrome / Chromium があればそちらを優先し、どのブラウザを開いたかは必ず画面に出します(Edge の音声認識は不安定なため) |
| **スマホ(リモート)** | **スマホのキーボードの音声入力**(Gboard の 🎤 / iOS の音声入力)を使います |

スマホだけ仕組みが違うのには理由があります。リモートは LAN 内の http なので、ブラウザの音声認識(HTTPS 必須)はそもそも動きません。以前はここで無言のまま再試行し続けていました。今はページがそれを検知して、**HTTPS も追加の権限も要らないキーボードの音声入力**へ案内します。iOS Safari や Firefox のように音声認識 API を持たないブラウザでも同じ案内が出ます。もちろん、文字が入るのは入力欄まで。**Enter を押すのは、やはりあなたです。**

自前の認識エンジンを使いたい場合は、これまでどおり `voice_command` を設定してください。macOS 以外では常にそれが最優先になります。

### 📝 そして、最後の一筆は自分の手で — Zed インスパイアのエディタ

AI が 9 割を書く時代でも、最後の 1 割——設計の勘所、名前の選び方、責任を持つ一行——は人間のものです。だから Zaivern は、指揮官の椅子のすぐ横に切れ味のいいペンを置きました。syntect による構文ハイライト、LSP 診断、Git 差分ガター、ファジーパレット(⌘P)、VS Code 同等のファイル操作とスクロール。**書きたくなった瞬間に、書ける。**

## なぜ Rust か — コックピットが重くては、話にならない

- **Electron も Node も無し。** egui による GPU 描画のネイティブバイナリ 1 個。起動は一瞬、アイドル時のメモリはブラウザのタブ 1 枚より軽い
- **見ているだけの時間には、CPU を使わない。** 常時再描画をやめ、次のフレームが本当に必要かを状態から判断する。実測(リリースビルド・30 秒窓)で**フォーカス時 0.13% / 非フォーカス時 0.03%**。`ZV_IDLE_TRACE=1` を付けて起動すれば、実 fps と判断根拠が毎秒出ます
- **本物の PTY ターミナル**(portable-pty + vt100)。Claude Code のフルスクリーン TUI がそのまま動く。256色 / TrueColor、ブラケットペースト、スクロールバック対応
- **macOS / Windows / Linux 同一コード。** アプリ終了時に子プロセスは自動 kill(孤児プロセスを残しません)
- 系譜: **Zed の速度 × Cmux の並列エージェント × AGI Cockpit の操縦席UX**

## 機能リファレンス

ここから下は、操縦席の計器ひとつひとつの説明書です。

### 📝 エディタ
- syntect による構文ハイライト(Rust / TS / Python / Go / Markdown ほか多数、拡張子から自動判定)
- タブ・行番号ガター・未保存インジケータ(●)・閉じる前の保存確認
- ファイルツリーで VS Code 同等のファイル操作: ➕新規ファイル / 📂新規フォルダ(インライン入力)、✏名前の変更(開いているタブのパス・言語も自動追従)、🗑削除(確認ダイアログ付き)
- 右クリックメニュー: 開く / 新規作成 / 名前変更 / 削除 / 「パスをエージェントに送信 (@path)」 / フルパスをコピー
- ファイル内検索(⌘F、ヒット件数表示・ヒット行へ中央ジャンプ)
- 括弧・引用符の自動ペア(開きで自動閉じ・選択を囲む・閉じはスキップ・空ペアは Backspace 一発で削除)
- VS Code 同等のスクロール: 固定ガター・scrollBeyondLastLine・PageUp/PageDown
- ファジー検索コマンドパレット(⌘P でファイル、⌘⇧P でコマンド、**`@` でエージェント、`#` で git worktree**。1 つの入力欄からファイル・コマンド・セッション・worktree を横断)
- **ドラッグ&ドロップ**: ファイルツリーの項目や OS のファイル/画像をエージェントのターミナルへ落とすと `@パス` が入力欄に入る(送信はしない)。エディタ側に落とせばタブで開き、フォルダはワークスペースに追加される
- **🖼 画像ビューア**: `png` / `jpg` / `jpeg` / `gif` / `webp` / `ico` をタブで開く。既定は「フィット」(ウィンドウに合わせる)、`−` / `＋` / `100%` ボタンと Ctrl(⌘)+スクロールで 0.05〜32 倍まで。透明部分は市松模様で描き、下に `幅×高さ px · ファイルサイズ` を出す(GPU 上限で縮小して表示した場合は「(表示は W×H に縮小)」と明記)。読み取り専用。アニメーション GIF は 1 コマ目のみ表示
- **📄 PDF をエディタで開く**: [pdf-extract](https://crates.io/crates/pdf-extract) でテキストを抽出し、`── ページ i / N ──` で区切った**読み取り専用**タブとして表示。⌘F のファイル内検索はそのまま効く。抽出はワーカースレッドで走り、250ms 以内に終われば即表示、遅いものは `⏳ 読み込み中…` を出してから差し替わる(UI は待たない)。32MB を超える PDF は抽出せず、その旨を表示する
- **↩ 折り返し / · 空白文字の表示**: 表示メニュー、またはコマンドパレットの「折り返し切替」「空白文字表示切替」で切替(スペース = `·` / タブ = `→`)。初期値は `config.toml` の `word_wrap` / `show_whitespace`(いずれも既定 `false`)、`.zaivern.toml` でプロジェクトごとの上書きも可
- **📐 折りたたみ・インデントガイド・スティッキーヘッダ・🔖 ブックマーク**: **⌥⌘[** で折りたたみ切替 / **⌥⌘]** で全展開(段数指定はコマンドパレット)。ネストの縦線と画面上端に残る親の見出し(最大 3 段)は常時描画。**⌥⌘B** で行にブックマークし、コマンドパレットから次 / 前へジャンプ。**⇧⌘T** で直前に閉じたタブを開き直す
- **✏ 複数キャレット / 矩形選択**: **⌘D** で次の一致を選んでキャレットを増やす。コマンドパレットから「カーソルを上 / 下に追加」「矩形選択の開始 → 確定」「全キャレットへ貼り付け」。取り消しは一括で 1 回
- **✂️ スニペットと Emmet**: VS Code 形式(`$1` / `${1:既定値}` / `${TM_FILENAME}`・`${1|a,b|}` の選択肢・ミラー)を Tab で展開。ユーザー定義は `~/.zaivern/snippets/` に `*.json` / `*.code-snippets` を置く(JSONC 可)。HTML / JSX 系では `ul>li*3` `div.cls#id` のような Emmet 略記も展開する
- **🔤 文字コードと改行コード**: 「エンコーディングを指定して開き直す / 保存する」をコマンドパレットから。候補は起動時に往復変換で実測した**このビルドで本当に読み書きできるものだけ**を並べる。改行コードは LF / CRLF / CR へ変換でき、混在は内訳を出す。保存時の「末尾空白を削る」「最終行に改行を入れる」は表示メニューで切替(既定オフ)
- **📊 CSV / TSV の表表示と大容量ファイル**: `.csv` / `.tsv` はコマンドパレットの「テーブル表示の切替」で表として読める。4MB 超は強調表示と折りたたみを止め、50MB 超は読み取り専用(効いている制限は上部の帯に明示)、512MB 超は開かない
- **👁 Markdown / HTML プレビュー**(**⌘⇧V**): GFM のテーブル・タスクリスト・脚注・autolink、front-matter の折りたたみ、生 HTML タグ、ローカル / `data:` 画像に対応。**```mermaid フェンスは図として描画**(`graph` / `flowchart` / `sequenceDiagram`。未対応の図種はその旨を出す)、`$…$` / `$$…$$` の TeX 数式も組む——**どちらも追加依存なしの純 Rust 実装**
- Git ブランチ表示、日本語 UI フォント自動フォールバック

### 👾 マルチエージェント
- エージェントプリセットをワンクリック起動(⌘⇧A)し、複数セッションを並列実行
- セッションごとの稼働状態(●/○)・稼働時間・再起動・強制終了
- **29 種の CLI エージェントを内蔵カタログで認識**。Claude Code / Codex / Grok / Cursor / GitHub Copilot / OpenCode / MiMo Code / Amp / OpenClaude / Antigravity / Pi / oh-my-pi / Hermes / Devin / Goose / Auggie / Autohand / Crush / Cline / Command Code / Continue / Droid / Kilo Code / Kimi / Kiro / Mistral Vibe / Qwen Code / Rovo Dev / Aider
- 権限モード(🛡承認 / ⚡全自動)はカタログのエージェントに自動適用される。**プリセット側でフラグを書く必要はない**し、一括承認フラグを持たない Goose / Aider には環境変数の側で適用される
- カタログに無い CLI エージェントも、プリセット登録すればそのまま並列起動できる
- 実行中のセッションには各行の 🛡 ボタン(または「🛡 全切替」)で権限モード切替を送信
- **未読マーカー (◆)**: 最後に見てから*意味的に*新しい出力があるセッションに ◆ が付く(スピナーや経過秒の揺れでは付かない)。タブ・サイドバー・Cockpit 共通。右クリック「📩 あとで見る」で手動の未読ピンも
- **レート制限の検知 (⏳)**: `usage limit reached` 等の警告を画面から検知してバッジ + 通知。**制限中のセッションには新しいタスクを割り当てない**。制限が明ければ自動で復帰
- **アカウント/プロファイル切替**: プリセットの `env` に `CLAUDE_CONFIG_DIR` / `CODEX_HOME` 等を書けば、**同じ CLI を別アカウント(別サブスク)で並列起動**できる(値先頭の `~/` は自動でホームに展開)
- **📜 ターミナルログの永続化**: 各セッションの生出力は `~/.zaivern/term_logs/` に残り(4MB でローテート、新しい 40 本を保持)、ターミナルパネルの 📜 から前回セッションのログを開ける。「昨夜どこまで進んだ?」に再起動後でも答えられる
- **💬 チャット履歴の再開は「明示的に選んだときだけ」**: 起動しただけでは**何も立ち上がりません**。過去の会話へ戻る口は 💬 セッションタブの 1 本に絞ってあります。`config.toml` の `restore_agents = true` にすると従来どおり前回のエージェントタブを自動で戻し、前回のスクロールバック(末尾 1MB まで)を `── 前回のセッションここまで / 再開します ──` の区切り付きで再生したうえで、**claude は `--continue`、codex は `resume --last`** を付けて会話を継ぎます。**環境変数は秘匿情報になり得るのであえて保存せず**、プリセット名で今の設定から引き直します
- **✉ エージェント個別の複数行入力欄(コンポーザ)**: Cockpit 下部の入力欄は宛先を指名でき、**Enter は改行・⌘(Windows / Linux は Ctrl)+Enter で送信**。下書きは宛先ごとに保持される。長いレビュー文を書いている途中の Enter が全員へ飛ぶことはない
- **💬 過去セッションのサイドバー / 📊 プラン使用量**: claude / codex が残したセッション記録を一覧から選んで**そのフォルダで再開**できる(`--resume <id>` を自動で付ける)。一覧に出るのは**いま開いているフォルダで交わした会話だけ** — ブランチ (worktree) 別にまとめる表示は持たないので、同じフォルダを開いている限り一覧は常に同じです(VS Code の Claude Code 拡張と同じ切り方)。ステータスバーには使用量の目安が出て、クリックで明細(アカウント別・実測値と推定値を区別・枯渇の見込み)。集計はオフラインで完結する
- **🔢 番号メニュー / アンケートで止まらない**: 「1. Yes」「Select an option [1-3]:」のような**番号入力待ち**を検出して自動応答する(スキップ→肯定→評価尺度の順で選ぶ)。答えた事実は「アンケートに自動で回答しました: n」としてイベントと監査ログに残る。意味のある自由選択・権限昇格は自動で答えず、承認待ちとして UI に出す
- **📋 クリップボードの画像をそのまま貼る**: エージェント端末で **⌘V**(Windows / Linux は **Ctrl+V**)。クリップボードに画像があれば PNG として一時ディレクトリの `zaivern-clip/` に保存し、入力欄へ `@パス` を差し込む(**送信はしない**)。クリップボードにテキストがあるときは従来どおりテキスト貼り付けが優先されるので、挙動が変わることはない。保存した PNG は新しい 24 枚だけ残して自動で掃除される

### 📋 フリート看板 — 8 レーンで全機の「いま」を見る
**⌘⇧K**(メニューの「フリート看板」、または画面上部の「📋 看板」タブ)。走っているエージェントを 1 枚ずつのカードにして、状態のレーンへ並べます。上には KPI タイル(稼働中 / 作業中 / 要対応 / 完了)。**Cockpit / デッキと同格の中央画面**なので、開くと常に**ウィンドウ全面**を使います。

- レーンは 8 つ: **待機 / 思考中 / 編集中 / 実行中 / 検証中 / 承認待ち / 停滞・異常 / 完了・終了**。カードの移動には 400ms のホールドを挟んでチラつきを抑え(承認待ち・停滞・完了だけは即時)、着地したカードは短く光る
- カードに載るもの: 活動チップ / その状態が続いている時間 / 直近に触ったファイル / 直近のコマンド / 最新の出力行 / 直近 30 秒の出力パルス
- **推定を事実として扱わない。** 判定は強い信号から順に降りる(プロセスの生死 → 承認待ち検出 → レート制限検出 → 見張りの判定 → 画面テキスト)。画面から読んだだけの推定には `≈`、確かな根拠のあるものには `✓` を付け、ホバーで出どころを見せる。見張りが「待機」と言っているのに、古い画面の文字で「実行中」を主張したりはしない
- カードからそのまま ✅承認 / ❌拒否 / 指示の送信 / 権限モード切替 / 再起動 / 終了。上部の入力欄から全員へのブロードキャストも
- **縦モード**あり(自動 / 横 / 縦をメニューで切替、選択は記憶される)。カードを選ぶとその端末が下にライブ表示され、↑↓ / j / k で移動、Enter でそのまま入力、Esc で看板へ戻る
- 見ているだけの時間にコストを払わない設計: PTY のサンプリングは出力中 150ms / 静止時 1 秒、再描画要求もアニメ中だけ 33ms、静止時 1 秒、全員終了後は 2 秒と段階的に緩める

### 🏁 プロンプト・ファンアウトレース — 1 つの指示を、N 体で並走させる
コマンドパレットの **「🏁 プロンプトレース (1 プロンプトを複数エージェントで並走)」** から開きます。どれが速いかではなく、**どれが良いか**を後から選ぶための仕組みです。

- プロンプトを 1 つ書き、走らせるプリセットを **2〜4 体**選ぶ。各体には `git worktree add -b race/<slug>-<i>` で**専用の作業ツリー**(リポジトリの隣、`<repo名>-race-<slug>-<i>`)を切り、そこを作業ディレクトリにエージェントを起動してからプロンプトを配達する
- 作業ツリーが汚れている / HEAD が detached のときは**そもそも始めない**。途中で worktree 作成に失敗したら、作りかけた分を巻き戻してから止まる
- ダッシュボードには各体の状態(準備中 / 🏃 走行中 / ⏹ 終了 / ✅ 採用済 / 🗑 破棄済)と ± の変更量が並ぶ。変更量は 4 秒ごとに**バックグラウンドで**取り直す(git を UI スレッドで呼ばない)。`Diff` ボタンで読み取り専用の差分タブが開く
- **採用**は `git merge --no-edit`。衝突したら `merge --abort` で戻すだけで、force はしない。**破棄**は `git worktree remove` + `git branch -D` で、残骸を残さない
- **衝突には、レビュー時ではなく走行中に気づく。** 各体が触ったファイルの集合(未コミット + コミット済みの両方)を同じ 4 秒周期で突き合わせ、2 体以上で重なっていれば `⚠ N ファイルが2体以上で競合`、行ごとにも `⚠ 衝突 a.rs, b.rs 他N件`。重なっていなければ `✓ 単独`
- 2 体目以降を採用しようとしたとき、**すでに採用したものとファイルが重なっていれば一度止めて確認を挟む**(「⚠ 採用済みの◯◯と◯◯が重なります」)。もう一度押せば進む——**禁止するのではなく、気づかせる**

### 🔌 プラグイン(自作して、配って、もらう)
シェルさえ書ければ誰でも作れます。`~/.zaivern/plugins/<名前>/` に置く 1 フォルダ + `plugin.toml` だけ。Rust も再ビルドも不要です。

- **▶ コマンド**: シェルコマンドを実行し、結果をエディタへ反映
  - `input` = `none` | `selection` | `file`
  - `output` = `replace` | `insert` | `new_tab` | `notify` | `silent` | `agent_prompt` | `panel` | `actions`
  - `langs = ["rust"]` で言語を絞り、`keybind = "cmd+alt+f"` でショートカット起動、`on_save = true` で保存時に自動実行(フォーマッタ向け)
  - タイムアウト付きバックグラウンド実行。実行中にバッファを編集した場合は上書きしません
- **📊 パネル**: サイドバーに独自の表示領域を追加(手動 / 開いた時 / 一定間隔で更新、Markdown 描画可)
- **🪝 フック**: 起動時・ファイル開閉・保存時・**エージェント完了時**・承認待ち・git 変更時・一定間隔で自動実行
- **⚙️ 設定項目**: ユーザーに入力させる値を宣言でき、`ZV_CFG_<KEY>` として渡ります
- **🎨 テーマ / ✂️ スニペット**: 一般的なエディタ互換形式をそのまま同梱できます

**アプリを操作する**: `output = "actions"` にすると、標準出力の各行が指示になります(JSON Lines)。

```sh
echo '{"action":"open_file","path":"src/main.rs","line":42}'
echo '{"action":"agent_prompt","agent":"claude","text":"この関数をテストして"}'
```

ファイルを開く・通知する・タブを開く・ターミナルで実行する・パネルを書き換える・**エージェントに話しかける**などが自由に行えます。`agent_prompt` は `submit` を明示しない限り**送信せず入力欄に置くだけ**なので、勝手に走り出すことはありません。

操作は 3 ボタン: **➕ 新規作成**(テンプレート一式を生成)/ **📤 エクスポート**(`.zvplug` を書き出して配布)/ **📦 インストール**(受け取った `.zvplug` / `.zip` を選ぶだけ)。

```toml
# plugin.toml の例: 保存時に JSON を自動整形
[plugin]
name = "json-fmt"
version = "0.1.0"
description = "保存時に JSON を整形"
api = 2

[[command]]
title = "JSON を整形"
run = "python3 -m json.tool"
input = "file"
output = "replace"
langs = ["json"]
on_save = true
keybind = "cmd+alt+f"
```

📖 **作り方の詳細は [docs/plugins.md](docs/plugins.md) にまとめてあります**(3 分で作る手順・全項目の一覧・アクション早見表・困ったときの対処)。

### ⌨️ コマンドラインから操作する
`zai` は、動いているエディタを外から操作できます。プラグインからも、**エージェント自身にも**使わせられます。

```bash
zai open src/main.rs --line 42     # ファイルを開く
zai notify "ビルドが通りました"       # 通知を出す
zai prompt "この関数をテストして"      # エージェントの入力欄へ差し込む(送信はしない)
zai run "cargo test"               # ターミナルで実行
zai status "デプロイ中"              # ステータスバーに表示
zai status                         # 起動中の Zaivern Code を一覧(PID / 版 / 稼働時間 / ワークスペース)
zai status --json                  # 同じ一覧を JSON で出力
zai plugin list                    # プラグイン一覧
zai plugin new <名前>               # 雛形を作る
zai app install                    # OS のアプリ一覧に登録(Launchpad/メニュー/スタートメニュー)
zai app uninstall                  # アプリ登録を解除
zai firewall status                # 📱 の受信許可を確認 (Windows)
zai firewall allow                 # 📱 の受信を許可 (TCP 8899-8919・管理者)
zai firewall revoke                # 受信許可を取り消す
```

引数なしの `zai` や `zai .` は今までどおり GUI が起動します。**フォルダを 1 つも指定せずに起動したときは、前回のフォルダを自動で開き直します**(`~/.zaivern/menu_state.toml` の最近使った順に見て、いま実在する先頭の 1 つ)。毎回カレントディレクトリで開きたいときは `zai --no-restore`、または環境変数 `ZAIVERN_NO_RESTORE=1` を付けてください。

**起動中インスタンスの検知。** 引数なしの `zai status` / `zai status --json` は、`~/.zaivern/instances/<pid>.json` の登録簿を読んで**いま動いている Zaivern Code を一覧**します。1 つでも動いていれば終了コード **0**、無ければ **1** なので、`zai status >/dev/null || zai .` のようにシェルからそのまま分岐できます。生死の判定は OS ごとに実装が分かれ(Linux は `/proc`、macOS は `kill(pid, 0)`、Windows は `tasklist`)、**PID の使い回しに引っかからないよう起動時刻の署名まで照合**します。文字列を渡す `zai status "..."` は従来どおりステータスバーへの表示で、意味は変わりません。

### 🔤 言語サーバー(LSP)
`rust-analyzer` / `typescript-language-server` / `pyright-langserver` / `gopls` が PATH にあれば自動起動し、診断(エラー/警告)を表示。行番号ガターが赤/黄に色付き、ステータスバーに `⛔件数 ⚠件数`。サーバーが無い環境でも通常どおり編集できます。

診断だけでなく、**VS Code と同じキーで一通り揃っています**: **⌃Space** 補完 / ホバーで型と説明 / **⇧F12** 参照を検索 / **⇧⌘O** シンボルにジャンプ / **F2** リネーム(複数ファイルにまたがる編集もまとめて適用)/ **⇧⌥F** ドキュメント整形。ツールバーの「🛠 保存時に整形」を入れると保存のたびに整形します(既定オフ)。サーバーが対応していない機能は、黙って何もせず「このサーバーは◯◯に対応していません」と伝えます。

導入例: `rustup component add rust-analyzer` / `npm i -g typescript-language-server typescript` / `npm i -g pyright` / `go install golang.org/x/tools/gopls@latest`

### ⌨️ 日本語入力(IME)
ターミナル内で日本語がそのまま打てます。変換中の未確定文字はカーソル位置に下線付きでオーバーレイ表示され、確定分だけがエージェントへ送信されます。

### 🌿 Git 行ガター
git リポジトリのファイルは行番号が差分で色分け(緑 = 追加行 / 黄 = 変更行)。ステータスバーにブランチ名 + 変更ファイル数(±N)。

### 🌳 ファイルツリーの git 表示とアクティブファイル追従
ファイルツリー側でも、どこが動いているかが一目で分かります。

- 変更のあるファイルには色分けバッジが付く: `M` 変更 / `A` 追加 / `U` 未追跡 / `D` 削除 / `R` リネーム / `C` コンフリクト
- **親フォルダも色が乗る**。`📁 src  M•3` のように、たたんだままでも「この下に 3 件の変更がある」と分かる(色は配下でいちばん重い状態)
- 状態は `git status --porcelain` を**バックグラウンドスレッドで** 2 秒間隔に取り直す。UI スレッドから git を呼ばないので、大きなリポジトリでもフレームは落ちない
- **🎯 アクティブファイル追従**(既定オン): エディタのタブを切り替えると、ツリーがそのファイルまで自動で展開してスクロールする。ワークスペースのルート行を右クリック →「🎯 アクティブファイル追従: ON / OFF」で切替。設定は次回起動にも引き継がれる

### 📚 マルチフォルダ・ワークスペース
複数のフォルダを同時に開ける。`zai dirA dirB dirC` のように引数を並べるか、コマンドパレットの「フォルダをワークスペースに追加」から後付けする。

- ファイルツリーはルートごとに見出しを立てて並ぶ(1つだけのときは従来通りの見た目)
- ファイル検索は全ルートを横断。**同じ相対パスが複数のルートにある場合だけ**、フォルダ名を前置して区別する
- git はルートごとに実リポジトリを検出(`rev-parse --show-toplevel`)するので、リポジトリのサブディレクトリを開いても差分が正しく出る。同じリポジトリ内の 2 ルートは 1 つの git 状態を共有する
- セッション復元はルートの集合をキーにする。並び順が変わっても同じワークスペースとして復元される

### 🐙 GitHub 連携
`gh` コマンド経由で Pull Request / Issue の一覧、PR の差分閲覧、ブランチ操作。**追加の認証設定は不要**(`gh auth login` 済みならそのまま使える)。`gh` が入っていない環境では機能が安全に無効化される。

差分は追加行 / 削除行を色分けしたインライン diff ビューで読める。

**⚡ Issue にワンクリックで着手。** Issue の「⚡ 着手」からエージェントを選ぶと、(1) その issue 専用の git worktree をリポジトリの隣に作成(ブランチ `wt/issue-N`、worktrees プラグインと同じ規約)、(2) ワークスペースへ追加、(3) そこを作業ディレクトリにエージェントを起動、(4) セッションが落ち着いたタイミングで着手指示を入力欄へ投入 — まで自動で繋がる。**Enter を押すのはあなた**なので、指示を直してから走らせられる。

### 🔎 変更をレビュー — PR を出す前に、PR のように読む
Git パネルの「変更をレビュー」(コマンドパレットの「変更をレビュー (PR 風のローカルレビュー)」)。**まだ push していないローカルの変更**を、GitHub の PR 画面と同じ形で読む場所です。

- 左に変更ファイル一覧(ディレクトリごと、ツリーと同じ色とバッジ、`+N −M`、上部に「N ファイル変更 · +X −Y」)。クリックでその差分へ飛び、`n` / `p` で前後のファイルへ。比較対象は **作業ツリー vs HEAD / ステージ済みだけ / 未ステージだけ / 任意のリビジョン**を切替。未追跡は全行追加として合成、バイナリは中身を出さず、巨大な差分は打ち切って明示する
- ファイルごとに ステージ / アンステージ / **破棄(二段階確認)** / エディタで開く。空白無視とコンテキスト行数(3 / 10 / 全て)も切替できる。git の実行は専用スレッド + 5 秒 TTL のキャッシュなので、差分が大きくてもフレームは落ちない

### 💬 差分へのインラインレビューコメント
PR の差分タブでも、レースの差分タブでも、この PR 風レビュー画面でも、**行をクリックしてその場にコメントを書けます**。

- コメントは「ファイル + 旧/新 + 行番号」に紐づくので、差分を読み直しても、スクロールで仮想化されても位置を見失わない
- スレッドごとに `解決` / `未解決に戻す` / `編集` / `削除`。ツールバーには「レビューコメント n 件 (未解決 m 件)」
- 未解決のコメントは**まとめて 1 通のプロンプトになる**。`以下のレビューコメントに対応してください:` に続けて `@パス:行`(削除行には `(削除行)`)・引用・本文が、ファイル順 → 行順で並ぶ。`コピー` で持ち出すか、**「エージェントに送る」でコンポーザの下書きへ流し込める**(差分を見ていたエージェント宛て。**入れるだけで送信はしない**ので、直してから Enter)。**解決済みは自動的に外れる**ので、直し終わった指摘を送り直すことはない

### 🧭 外部 IDE で開く
いま編集しているファイルを、**カーソル行を保ったまま**別のエディタで開く。VS Code / Cursor / Zed / Trae / Kiro / Sublime / JetBrains 各種 / Xcode / Fleet / Neovide / Emacs に対応。

インストール済みの IDE は自動検出する。`code` コマンドが VS Code ではなく別製品のものに置き換わっている環境でも、実体を解決して正しく判別する。CLI が用意されていないアプリには URL スキームで受け渡す。

### 🔭 エージェント監視と再割り当て
複数のエージェントを走らせると、どれかが黙って止まる・同じ失敗を繰り返す・落ちる、といったことが起きる。それを検知して手を打つ層。

- **検知**: 停滞(進捗のない沈黙)、ループ(同じ出力の反復)、エラーの多発、異常終了、承認待ちの放置、出力の暴走。スピナーやカウンタは「進捗ではない」と正しく扱う
- **見張りは、検知と通知に徹する**: 自動承認・促し・再起動・停止をエージェントへ勝手に投げない。異常はバッジ・トースト・通知であなたへ上がり、手を打つのはあなた。**エージェントの入力欄へ黙って文字が流れ込む経路は存在しない**
- **再割り当て**: 止まったタスクを別のエージェントへ引き継ぐ。一度失敗したエージェントには同じタスクを振り直さない。**前の担当が停止したと確認できるまで引き渡さない**(二重編集を防ぐため)。試行回数を使い切ったらループせずユーザーへ上げる
- **エージェント間通信**: 相手が待機中のときだけメッセージを届ける(生成中の割り込みは入力を壊すため)。ホップ数上限・流量制限・往復の検出があり、届かなかったメッセージは理由付きで記録される

**仕事を配る。** コックピットから「タスク」を作って、特定のエージェントに振るか、自動割り当てに任せる。一覧には状態・担当・試行回数が並び、システムが諦めた `NeedsUser` は赤く目立つ。割り当てを断られたときは、理由がそのまま日本語で出る(黙って何も起きない、が一番困る)。

**エージェント同士で連絡させる。** 手動で送るほかに、エージェントが出力の行頭にこう書けば、そのまま相手へ届く。

```
[ZAI-TO:backend] マイグレーションが通ったので API 側を進めてください
[ZAI-TO:ALL] 共通の型定義を types.ts へ移しました
```

LLM に「宛先っぽい文」を推測させるようなことはしない。**行頭のマーカーだけを見る決定的な方式**にしてある。注入されたメッセージが画面に反射しても、それが新しい送信として二重に流れることはない(そこを間違えるとメッセージが無限に増殖する)。

### 🛡 統合承認キュー — 全エージェントの「許可して?」を 1 本に
エージェントが 5 体走っていると、承認プロンプトは 5 つの端末に散らばります。それを 1 つのキューへまとめる層です。パネルの **「🛡 承認」タブ**(待ち件数がバッジで出る / コマンドパレットの「承認キューを開く」でも開く)。

- 要求は 9 種に分類される: 読み取り / 書き込み / 削除 / シェル実行 / ネットワーク / git 操作 / パッケージ導入 / **権限昇格** / その他。キーボードだけで上から捌ける
- **ポリシー**で「この種別は、この範囲では常に許可 / 常に拒否」を宣言できる。範囲は `global` / `agent` / `session` / `path` の 4 つで、**具体的なものが勝つ**(`/repo/src/secret` の指定は `/repo` を上書きする)。`config.toml` の `[[approval_policies]]` に書けば起動時から効く。ただし **権限昇格(sudo 相当)だけは、ポリシーでも自動承認にできない**——`allow_always` を書いても弾かれ、その 1 件だけの承認になる
- 判断は追記専用の監査ログ `~/.zaivern/approvals.jsonl` に残る(種別 + 対象の頭 160 文字まで。コマンド全文や貼り付けられた秘密は書かない)。パネルから末尾を読める

### 💡 スーパーエージェント(指揮役)— 見張りに、頭脳を足す
監視そのものは Rust のルールで動いている。停滞やループを見つけるのに LLM は要らないし、**見張り役が LLM だと、見張り役が壊れたときに誰も気づけない**。だから検知は決定的なコードに任せてある。

そのうえで「で、どうするのが正解か」の判断を、AI に任せられる。コックピットの「💡 スーパーエージェント」で、**起動中のエージェントから 1 体を「指揮官」に指名する**だけ。指揮官が画面に `@対象: 指示`(全員宛は `@all:`)と書く——それが指揮のすべて。

- 既定は **「なし」**。指名しなければ指揮は一切動かない
- **起動中のどのエージェントでも指名できる**し、作業の途中でいつでも交代できる。唯一の例外は素のシェル——コマンド出力のエコーを指示と誤検出しやすいので、そもそも選択肢に出さない
- 指揮官の指示は **📮 通知としてあなたへ届く**。**どのエージェントの入力欄にも自動では書き込まない**——実際に流すかを決めるのはあなた(Cockpit の一斉送信や各端末への手入力で)。以前は各端末へ自動注入していたが、入力中の欄に勝手に文字が流れ込むため廃止した
- 通知に載せる本文は**伏字処理と長さ制限**を通す。解釈できない行からは**何もしない**。曖昧な答えから行動をひねり出す見張り役は、黙っている見張り役より危ない
- 破壊的な操作は、そもそも表現できない。停止や再起動を指揮官が投げることはない
- **指揮官も、ほかと同じように監視される**。特別扱いすると、そこが単一障害点になる
- 指揮官は**普通の作業にもそのまま使える**。監視専用に一枠を潰す必要はない

### 💾 セッション復元
再起動時に前回のタブ・アクティブタブ・パネル状態をワークスペースごとに自動復元(`~/.zaivern/sessions/`)。エージェントタブは **`restore_agents = true`(既定 `false`)にしたときだけ**戻ります。

**開いていたフォルダごと戻す。** フォルダ引数なしで `zai` を起動したときは、最近使ったフォルダ(`~/.zaivern/menu_state.toml`)を新しい順に見て、**いま実在する先頭の 1 つ**を開き直します。常にカレントディレクトリで始めたいときは `zai --no-restore`、または `ZAIVERN_NO_RESTORE=1`。

### 🧯 内部エラーからの自己回復(と、Windows のフリーズ根治)
- 描画中に内部エラー(panic)が起きても、**アプリごと落とさない**。10 秒の窓で同じ場所が 3 回壊れたら、**その部分だけを描画から外して**残りは動かし続ける。画面上部に「⚠ ◯◯ で内部エラーが繰り返し起きています。壊れた部分の描画を止めました」というバナーが出て、`閉じる` で畳む / `再試行` で隔離を解いて描き直す。外した場所には「◯◯ の表示を停止しました」が残る。詳細は `~/.zaivern/panic.log`(古い分は `panic.log.old`)
- 隔離の記憶は**時間で減衰する**。300 フレーム無事に描けて窓が空になれば元に戻るので、何時間動かしても「ずっと前の 1 回」で機能が削られていくことはない。3 回連続の panic か、隔離が 3 回を超えたときだけ諦める
- **Windows Cockpit のフリーズは 3 方向から塞いだ**: (1) ウィンドウリサイズ中の ConPTY への要求を合流させ、**同じサイズが 2 フレーム続いてから 1 回だけ**送る(専用スレッドが常に最新の値だけを持つので、UI スレッドは待たされない)、(2) ファイルダイアログを別スレッドへ逃がし、開いている間も UI が固まらない(macOS は NSOpenPanel がメインスレッド専用なので従来どおり同期)、(3) 上の panic 隔離。**「名前を付けて保存」はタブ位置ではなくバッファ ID を握る**ので、ダイアログを開いている最中にタブを並べ替えても別のファイルへ書き込まない
- **端末が「黒いタイル」で残る問題は、原因の側で塞いだ。** vt100 パーサのスクロール領域・タブストップ・行操作で起きていた panic と、`CSI <巨大な数値>` の反復パラメータの暴走を上限で抑え込んだ(パッチは `vendor/vt100` に取り込み、敵対的入力のテストで固定)。それでも壊れたタイルは 1 枚だけを隔離して「⚠ 再試行」を出す——**空の黒い矩形のまま放置しない**。併せて、プラグインのタイムアウト時に**孫プロセスまで木ごと止める**(取り残しでエディタが固まっていた)、日本語入力の変換確定 Enter がエージェントへ漏れる問題、CP932 など非 UTF-8 保存の破損も塞いだ

### 📱 スマホリモートの詳細
- **できること**: ファイルの閲覧・編集・保存、タブ切替、ワークスペース検索&オープン、エージェントのターミナル閲覧・指示送信・承認操作(Enter / Esc / ^C / ↑ / ↓ / Tab / ⇧Tab / 1 / 2 / 3 / y)、各種コマンド(保存・新規・Cockpit・フォント±・承認モード切替など)
- **仕組み**: 内蔵の極小 HTTP サーバ(ポート 8899、使用中なら 8900〜8919 に自動フォールバック)。依存クレート追加なしの `std::net` のみ
- **セキュリティ**: 起動ごとにランダム生成されるトークンで認証(QR の URL に埋め込み済み)。トークンなしの API アクセスは 401 拒否。LAN 内のみ
- **Windows の受信許可**: Windows は既定で受信をブロックするため、規則が無いとスマホから接続できない。📱 画面が状態を自分で調べ、無ければ「🛡 受信を許可する (管理者)」を出す。作る規則は **この `zai.exe` + TCP 8899-8919** だけに絞り、プロファイルは Domain/Private——ただし**いま繋いでいるネットワークが「パブリック」に分類されている場合は Public も含める**(家の Wi-Fi がパブリック扱いなのは珍しくなく、含めないと直らない)。その事実は画面にそのまま出るので、公共 Wi-Fi では 📱 を使わないこと。「キャンセル」で作られてしまった**拒否規則も許可時に削除する**(Windows は拒否を優先するため、残っていると許可しても通らない)。取り消しは 📱 画面のボタンか `zai firewall revoke`。インストーラは管理者で実行されていればこの規則をその場で作り、そうでなければ案内だけ出す(勝手に昇格しない)

## インストール(手動)

ワンライナー(冒頭参照)が最速です。`install.sh` は GitHub Releases のビルド済みバイナリを `~/.local/bin/zai` へ配置し、対応バイナリが無い環境では Rust(無ければ rustup ごと自動セットアップ)でソースからビルドします。すでにインストール済みの場合は最新版への**更新**として動作します(古い `zai` が別の場所に残っていれば、そちらも同時に更新します)。

- **ビルド済みバイナリ**: [Releases](https://github.com/tacyan/zaivern-code/releases/latest) から自分の OS のアーカイブを取得し、展開した `zai`(Windows は `zai.exe`)を PATH の通った場所へ
- **ソースから**(要 Rust):

```bash
cargo install --git https://github.com/tacyan/zaivern-code --locked
```

`~/.cargo/bin/zai` に配置されます。

### ビルドと起動

```bash
# 要 Rust 1.88+(rustup update stable)
cargo build --release

# 起動(引数でワークスペースを指定。省略時はカレントディレクトリ)
./target/release/zai ~/dev/my-project

# 複数のフォルダを同時に開く
./target/release/zai ~/dev/frontend ~/dev/backend ~/dev/shared

# ファイルを引数に混ぜるとタブとして開く
./target/release/zai ~/dev/my-project README.md
```

macOS / Windows / Linux で同一コードのままビルドできます(Linux は要 `libgtk-3-dev` 等の rfd 依存)。

### テスト

```bash
cargo test        # 手元ではこれで全件 (macOS / Windows / Linux 実機)
```

CI と同じ回し方を手元で再現したいときは [cargo-nextest](https://nexte.st/) を使います。

```bash
cargo install cargo-nextest --locked
cargo nextest run --locked --no-fail-fast --profile ci
```

`ci` プロファイルは `.config/nextest.toml` に定義してあり、1 件あたり 60 秒(実 PTY テストは 45 秒)で打ち切り、失敗は即時に出したうえで最後にもう一度まとめて出します。**実 PTY テスト**——シェルを実際に起動する `terminal::pty_tests` / `pty_writer_tests` / `reap_pty_tests` / `pty_resize_tests` の 4 モジュール——は `pty` テストグループとして**1 スレッドに直列化**されます。

GitHub Actions では **3 OS × `fast` / `pty` の 6 ジョブ**を並列に回し、この 2 群をジョブごと分けています。

```bash
# fast: 実 PTY 以外のすべて (並列)
cargo nextest run --locked --no-fail-fast --profile ci \
  -E 'not test(/^terminal::(pty_tests|pty_writer_tests|reap_pty_tests|pty_resize_tests)::/)'

# pty: 実 PTY だけ (直列)
cargo nextest run --locked --no-fail-fast --profile ci \
  -E 'test(/^terminal::(pty_tests|pty_writer_tests|reap_pty_tests|pty_resize_tests)::/)'
```

分けている理由は Linux と PTY の相性ではなく、GitHub のホステッド Linux ランナー(2 コア / 7GB)で実 PTY を並列に立てるとリソースを使い切り、**ランナープロセスごと落ちてログもアーティファクトも残らない**ためです。直列化するのは上の 4 モジュール(Linux / macOS で 18 件、`pty_tests` が Unix 限定の Windows では 12 件)だけで、`terminal::` の残りは `fast` 側で普通に並列に走ります。`--no-fail-fast` を付けているのは、1 回の実行で**すべての失敗を洗い出す**ためです。

> 以前ここには「Linux では `cargo test -- --skip terminal::` で `terminal::` をまるごと除外する」と書いていました。**もう不要です。**

## カスタマイズ — `~/.zaivern/config.toml`

初回起動時に自動生成されます。編集後はコマンドパレットの **「設定を再読み込み」** で即反映(パレットから **「設定 config.toml を開く」** で直接編集も可能)。

```toml
# テーマ: "zaivern-dark" | "zaivern-midnight" | "zaivern-light"
# または VS Code 互換テーマJSONへのフルパス
theme = "zaivern-dark"
editor_font_size = 15.0
terminal_font_size = 13.0
show_hidden_files = true

# エディタ本文の折り返しと空白文字 (·/→) の可視化
# (表示メニュー・コマンドパレットの「折り返し切替」「空白文字表示切替」でも変更できます)
# word_wrap = false
# show_whitespace = false

# フォルダを開き直したとき、前回のエージェントタブを復元して会話を再開する
# 既定は false — 起動しただけでは何も立ち上がりません。過去の会話は
# 「💬 セッション」タブから選んで再開します。
# true にすると前回のスクロールバックが見える状態で、claude は --continue /
# codex は resume --last 付きで起動します。
# restore_agents = false

# 既定の権限モード (カタログ収録の 29 種すべてに自動適用)
#   "ask"   = 毎回ユーザー承認が必要(安全・デフォルト)
#   "auto"  = すべて自動YES(各CLIの bypass フラグを自動付与)
#   "agent" = Agent欄優先(プリセットのコマンドに書かれたフラグをそのまま使う)
approval_mode = "ask"

# 外出先への通知: ntfy のトピック URL / Slack / Discord の Incoming Webhook
# 承認待ち・終了・レート制限を POST する ("" = 無効)
# webhook_url = "https://ntfy.sh/あなたのトピック名"

# デスクトップペット 🐾
show_pet = true
# pet_variant = "blocky"   # 見た目: "blocky" | "crab" | "cat" | "cloud"
# pet_scale = 1.0          # 大きさ: 0.75=小 / 1.0=中 / 1.4=大
# pet_free_roam = true     # うろうろ散歩
# pet_sleep = true         # 無操作で睡眠
# pet_sounds = true        # 効果音
# pet_bubbles = true       # 承認バブル
# pet_auto_yes = false     # 承認プロンプトへ自動でYES (オフ=ユーザー承認必須)
# pet_approve_keys = "\r"    # 承認時にPTYへ送るキー (Enter)
# pet_deny_keys = "\u001B"   # 拒否時にPTYへ送るキー (ESC)

# ── 統合承認キューのポリシー(既定は空 = 全部あなたに聞く)──
# [[approval_policies]]
# kind = "file_read"         # file_read/file_write/file_delete/shell_command/
#                            # network_access/git_operation/package_install/
#                            # privilege(常に手動)/other
# scope = "agent"            # "global"|"agent"|"session"|"path" — 具体的な方が勝つ
# target = "claude"          # scope の対象 (global は空)
# decision = "allow_always"  # "ask"|"allow_once"|"allow_always"|"deny_always"

# ── 自動YESの追加ルール(同梱の応答表より先に評価される)──
# CLI が承認プロンプトの文言を変えたとき、再ビルドせずここで直せる
# [[auto_yes_rules]]
# pattern = "Do you want to proceed?"  # 一致したら reply を PTY へ送る
# reply = "\r"                         # agent = ""(既定)なら全エージェント

# ── AIエージェントのプリセット(いくつでも追加可能)──
[[agents]]
name = "Claude Code"
icon = "👾"
command = "claude"

[[agents]]
name = "Claude Code (全自動)"
icon = "⚡"
command = "claude --dangerously-skip-permissions"

[[agents]]
name = "Codex"
icon = "💡"
command = "codex"

[[agents]]
name = "Codex (全自動)"
icon = "⚡"
command = "codex --dangerously-bypass-approvals-and-sandbox"

[[agents]]
name = "Gemini CLI"
icon = "✨"
command = "gemini"

[[agents]]
name = "Antigravity"
icon = "🚀"
command = "agy"

[[agents]]
name = "Shell"
icon = "🖥"
command = ""          # 空文字はログインシェル

# [[agents]]
# name = "Claude (Opus 明示)"
# icon = "💡"
# command = "claude --model claude-opus-4-8"
# env = { MAX_THINKING_TOKENS = "31999" }
```

- `command` はログインシェル(`$SHELL -lc`)経由で実行されるため、PATH や alias がそのまま使えます。
- `env` でプリセット固有の環境変数を注入できます(モデル指定・APIキー切替などに)。
- `cwd = "~/some/dir"` で作業ディレクトリを固定できます(省略時はワークスペース)。
- **プロジェクトごとの上書き**: ワークスペース直下に `.zaivern.toml` を置くと、テーマ・フォント・承認モード・追加エージェントをプロジェクト単位で設定できます。
- **UI での選択は `~/.zaivern/state.toml` に自動保存**されます(テーマ・承認モード・ペット関連)。手書きの config.toml を汚しません。「設定を再読み込み」実行時は config.toml が優先されます。

### 指揮の小ワザ
- ファイルツリーで右クリック →「👾 パスをエージェントに送信」で `@path ` が入力される(Claude Code のファイル参照記法)
- コマンドパレット →「現在のファイルをエージェントに送信 (@path)」
- Cockpit のブロードキャストで、複数の Claude Code セッションに同じ指示を一斉送信
- 承認待ちはペットの承認バブルから ✔承認 / ✖拒否 をワンクリック、外出先はスマホリモートから
